# Окно настройки обвеса оружия

## Обзор

Окно открывается пунктом «Настроить обвес» в контекстном меню оружия, у которого в конфиге есть `customize_bones`. Все детали, которые встают на оружие (прицелы, крепления, цевья, магазины, фонари), — настоящие предметы. Они переходят из рюкзака на оружие и обратно, ничего не создаётся и не пропадает.

Движок даёт три части:

1. Пункт меню и вызов Lua-функции, которую задаёт мод.
2. Модуль `weapon_customize`: дерево узлов, раскладка, конфликты и применение изменений одним шагом.
3. Виджет `CUIWeaponViewport`: 3D-вид оружия с деталями, камера, точки узлов, примерка и выноски.

Само окно делает мод. В HD HUD оно лежит в аддоне `RenewedPerceptionSWP` и включается, только если подключены `RenewedPerceptionCoP` и Secret Weapon Pack (`secret-weapon-pack`). Без мода пункт меню открывает отладочное окно ImGui, как раньше (только в сборках с `DEBUG_DRAW`).

## Что видит игрок

1. Слева — дерево узлов, разбитое на группы: «Оптика и прицелы», «Дуло», «Корпус», «Эргономика», «Тактические модули», «Питание». Вложенные узлы (прицел на кронштейне, планки на цевье) идут со сдвигом под своим родителем. Справа от имени узла — установленная деталь, «пусто» или «нет деталей».
2. В центре — оружие в 3D со всеми деталями. На каждом узле есть точка: светлая — деталь стоит, серая — узел пуст. Выбранный узел подсвечен и подписан выноской, узел под курсором подписан второй выноской.
3. Справа — детали для выбранного узла: установленная, «Снять деталь», детали из рюкзака (со счётчиком) и детали на другом узле этого оружия. Детали, которых у игрока нет, показываются только в режиме бессмертия (`g_god 1`) и в режиме разработки. У каждой карточки цветная метка состояния.
4. Наведение на карточку примеряет деталь: она видна на оружии, хотя ещё не установлена. Примерка — только картинка в окне: предмет никуда не переносится и не создаётся, на оружии и в сохранении его нет.
5. Под видом — характеристики сборки. При примерке рядом с ними видна разница: зелёным то, что станет лучше, красным — то, что станет хуже.
6. Внизу справа — описание детали, её состояние и предупреждения: что она заменит, какие несовместимые детали снимутся и что уйдёт в рюкзак вместе с ними (например, прицел на снимаемой крышке ствольной коробки).
7. Сверху — название оружия, сколько узлов занято и масса сборки. Внизу — полоса хоткеев по текущим биндам.
8. Короткие сообщения сверху вида: «Установлено», «Снято», «Нет в рюкзаке», «Действие отменено».

## Управление

Мышь:

| Действие | Что делает |
| --- | --- |
| ЛКМ и тянуть по виду | Вращать оружие |
| ПКМ или СКМ и тянуть | Сдвинуть вид |
| Колесо над видом | Масштаб |
| Клик по точке узла | Выбрать узел |
| Клик по строке узла | Выбрать узел |
| Наведение на карточку | Примерить деталь |
| Клик по карточке | Установить деталь, «Снять деталь» — снять |

Клавиши переназначаются в меню управления, группа «Настройка оружия»:

| Действие | Клавиши | Геймпад | Что делает |
| --- | --- | --- | --- |
| `wc_slot_prev`, `wc_slot_next` | Q, E | LB, RB | Предыдущий и следующий узел |
| `wc_part_prev`, `wc_part_next` | W, S / ↑, ↓ | крестовина вверх, вниз | Выбор детали |
| `wc_apply` | Enter / Пробел | A | Установить выбранную деталь |
| `wc_detach` | X / Delete | X | Снять деталь с узла |
| `wc_undo`, `wc_redo` | Z, Y | Y (отмена) | Отменить и повторить |
| `wc_revert` | Backspace | Back | Вернуть сборку, которая была при открытии окна |
| `wc_focus` | F | RS | Камера следует за узлом / общий вид |
| `wc_reset_view` | R | LS | Сбросить камеру |
| `wc_rotate_left`, `wc_rotate_right` | A, D / ←, → | крестовина влево, вправо | Повернуть на шаг |
| `wc_zoom_in`, `wc_zoom_out` | = , - / Num+, Num- | RT, LT | Масштаб |
| `wc_close` | | B | Закрыть |

Esc закрывает окно. Под окном остаётся инвентарь.

## Настройка мода

### Подключение окна

```ini
[weapon_customize]
ui_functor = ui_weapon_customize.open
```

Движок вызывает `ui_functor(obj)` для оружия, на котором нажали пункт меню. Функция должна вернуть `true`, если открыла окно. Если секции нет, функции нет или она вернула `false`, открывается отладочное окно.

Подпись пункта меню — строка `st_weapon_customize`. Если строки нет, остаётся «Customize».

### Данные окна HD HUD

В `configs/mod_system_weapon_customize_swp.ltx` остаются только вызов окна, звуки, камера и хоткеи:

| Поле | Что задаёт |
| --- | --- |
| `xml` | Файл разметки в `configs/ui` |
| `refresh_ms` | Как часто проверять, не изменился ли обвес и рюкзак |
| `focus_zoom` | Масштаб, когда камера следует за узлом |
| `rotate_step` | Шаг поворота клавишами, в градусах |
| `snd_open`, `snd_close`, `snd_select`, `snd_attach`, `snd_detach`, `snd_error` | Звуки |

Подписи узлов, группы и характеристики лежат в `configs/ui/weapon_customize.xml`:

```xml
<groups>
	<group id="optics" label="wc_group_optics" order="10"/>
</groups>
<slots>
	<slot bone="tag_mount_attach" label="wc_slot_mount" group="optics" order="10"/>
</slots>
<stats>
	<stat id="weight" label="wc_stat_weight" key="inv_weight" mode="sum" include_root="1" format="%.2f" unit="wc_unit_kg" better="lower"/>
</stats>
```

1. `group` — `id`, строка `label`, порядок `order`.
2. `slot` — кость `bone`, строка `label`, группа `group`, порядок `order`. Узел без своей строки получает имя кости и группу `other`.
3. Новый узел нового оружия получает подпись одной строкой `slot`. Деталь получает имя из своего `inv_name`; для деталей SWP имена лежат в `configs/text/*/st_weapon_customize_swp_parts.xml`.

### Характеристики

Узел `stat`, по порядку вывода:

| Атрибут | Значение |
| --- | --- |
| `label` | Строка подписи |
| `key` | Параметр секции детали |
| `mode` | `sum` — сумма, `mul` — произведение, `max` — максимум, `any` — есть ли хоть у одной детали `key = true`, `first` — имя первой детали с этим параметром (так показывается прицел), `count` — число деталей |
| `include_root` | `1` — учитывать секцию самого оружия |
| `format`, `unit` | Формат числа и строка единицы |
| `better` | `higher`, `lower` или `none`: цвет разницы при примерке |
| `hide_zero` | `1` — не показывать, если значение 0 и при примерке не меняется |
| `hide_default` | `1` — не показывать, если значение 1 и не меняется |
| `empty` | Строка для `first`, если подходящей детали нет |

### Разметка

`configs/ui/weapon_customize.xml`. Окно само раскладывает панели под пропорции экрана, поэтому в разметке задаются стили, а не координаты:

1. `<layout>` — поля, ширина боковых панелей (минимум, максимум, доля ширины экрана), высота полосы характеристик, строк и карточек.
2. `<colors>` — цвета текста, состояний, точек узлов и выносок.
3. `<groups>`, `<slots>`, `<stats>` — см. выше.
4. Узлы `background`, `main_frame`, `panel`, `slot_row`, `part_card`, `marker`, `callout` и другие — текстуры и шрифты. Используются рамки RP2 из HD HUD.
5. `<viewport fov="20" zoom_min="0.6" zoom_max="4.5" auto_rotate="0"/>` — вид.
6. `<hotkeys>` — полоса хоткеев, формат как у `hotkey_bar` ([хоткеи](hotkeys.md)). Плашки клавиш (`key_back`, `key`, `label`) заданы прямо в узле: компактнее стиля ПДА.

Отдельные `_16` и `_21` файлы не нужны.

## Lua

### Модуль `weapon_customize`

Все функции принимают id объектов. Менять можно только оружие в инвентаре актора.

| Функция | Что делает |
| --- | --- |
| `slots(root)` | Все узлы дерева. Узел: `owner`, `owner_section`, `bone`, `depth`, `parent` (номер узла-родителя в этом же списке, 0 у верхних), `allowed` (секции), `attached` и `attached_section`, если узел занят. |
| `layout(root)` | Текущая раскладка: список `{id, owner, bone, section}` |
| `signature(root)` | Число, которое меняется при любом изменении обвеса |
| `conflicts(root, part, owner, bone)` | Детали, которые снимутся, если поставить `part` на узел: занятая деталь узла и несовместимые по `conflicts` |
| `attach(root, part, owner, bone)` | Поставить деталь на узел. Деталь берётся из рюкзака или с другого узла этого оружия, деталь на узле уходит в рюкзак. |
| `detach(part)` | Снять деталь в рюкзак вместе со всем, что на ней стоит |
| `apply_layout(root, layout)` | Привести обвес к раскладке из `layout()`: лишнее уходит в рюкзак, нужное ставится из рюкзака. Так работают отмена и сброс. |
| `parent(id)`, `root(id)` | Деталь, на которой стоит деталь, и оружие в корне |
| `is_customizable(id)` | Есть ли у предмета узлы |
| `actor_parts()` | Свободные предметы в рюкзаке: `{id, section, condition}` |
| `open_debug(id)` | Открыть отладочное окно ImGui |

Изменения доходят до оружия через события владения, поэтому новая раскладка видна в `slots` и `signature` не сразу, а в одном из следующих кадров.

### Виджет `CUIWeaponViewport`

Создаётся `xml:InitWeaponViewport(путь, родитель)`. Координаты точек — в системе виджета.

| Метод | Что делает |
| --- | --- |
| `SetItem(id)` | Какое оружие показывать |
| `Rotate(dyaw, dpitch)`, `SetAngles(yaw, pitch)` | Поворот, радианы |
| `Zoom(шаги)`, `SetZoom(k)`, `SetZoomLimits(min, max)`, `SetFov(градусы)` | Масштаб и угол обзора |
| `FocusSlot(owner, bone)`, `ClearFocus()`, `ResetView()` | Плавно навести камеру на узел, на всё оружие, сбросить вид |
| `SetAutoRotate(bool)` | Медленно вращать, если игрок ничего не трогает 4 секунды |
| `HasSlotPoint(owner, bone)`, `GetSlotPoint(owner, bone)` | Есть ли точка узла на экране и где она |
| `GetSlotCount()`, `GetSlotOwner(i)`, `GetSlotBone(i)` | Узлы в порядке отрисовки, нумерация с 0 |
| `GetHoverSlot()` | Узел под курсором или -1 |
| `PopClickedSlot()` | Узел, по которому кликнули после прошлого вызова, или -1 |
| `IsDragging()` | Игрок вращает или двигает вид |
| `SetPreview(owner, bone, section)`, `ClearPreview()`, `HasPreview()` | Примерка детали на узел. Текущая деталь узла на это время скрыта. |
| `SetCallout(owner, bone, x, y)`, `ClearCallouts()` | Выноска: линия от точки узла к точке `x, y` |
| `SetSelected(owner, bone)`, `SetLineColors(обычная, выбранная, пустая)` | Цвет выносок |

### Хуки окна HD HUD

`ui_weapon_customize.hooks` — функции, которые другой скрипт может подставить:

| Хук | Когда вызывается |
| --- | --- |
| `opened(wnd)` | Окно открылось |
| `rebuilt(wnd)` | Окно перечитало дерево узлов и рюкзак |
| `show_missing()` | Показывать ли детали, которых нет в рюкзаке. Без хука — только при `g_god 1`. |
| `missing_part(wnd, card, slot)` | Игрок выбрал деталь, которой у него нет. `true` — хук обработал выбор, сообщение «Нет в рюкзаке» не показывается. |

### Режим разработки

`scripts/ui_weapon_customize_dev.script` и `configs/mod_system_weapon_customize_dev.ltx` позволяют проверять детали, которых нет в рюкзаке:

```ini
[weapon_customize_dev]
enabled           = true
auto_install      = true
spawn_all_on_open = false
```

| Поле | Что делает |
| --- | --- |
| `enabled` | В списке видны все совместимые детали; клик по детали «нет в наличии» создаёт её в рюкзаке. Сообщение начинается с «DEV:». |
| `auto_install` | Созданная деталь сразу ставится на выбранный узел; это обычная установка, её можно отменить. |
| `spawn_all_on_open` | При открытии окна создать по одной детали каждого совместимого вида, которой нет ни в рюкзаке, ни на оружии. Узлы, которые появятся после установки детали (прицел на кронштейне), заполняются при следующем открытии. |

Перед выпуском удалите оба файла или поставьте `enabled = false`.

### Полоса хоткеев в своём окне

`xml:InitHotkeyBar(путь, родитель)` создаёт `hotkey_bar` из разметки скриптового окна.

## Ограничения

1. Детали, которых нет в рюкзаке, видны только с `g_god 1` или в режиме разработки. Конфликты для них считаются по полю `conflicts` в секциях, без вложенных деталей.
2. Отмена и сброс возвращают только те детали, которые ещё лежат в рюкзаке. Выброшенная или проданная деталь не вернётся.
3. Примерка рисует деталь без её собственных узлов.
4. Характеристики считаются по параметрам секций; урон, кучность и отдача из апгрейдов не учитываются.
5. Если оружие покинуло инвентарь, окно закрывается.

## Проверка после сборки

1. С HD HUD и SWP контекстное меню AK-74 показывает «Настроить обвес», окно открывается поверх инвентаря. Без SWP аддон `RenewedPerceptionSWP` пропускается (в логе «missing dependencies»), пункт открывает отладочное окно.
2. На 16:9, 21:9 и 4:3 панели не наезжают друг на друга, точки узлов квадратные.
3. ЛКМ вращает, ПКМ двигает, колесо масштабирует; при отпускании кнопки за пределами вида вращение прекращается.
4. Клик по точке и по строке выбирает узел, камера плавно наводится на него; F переключает общий вид.
5. Наведение на карточку показывает деталь на оружии и разницу характеристик; уход с карточки убирает примерку.
6. Установка из рюкзака: деталь пропадает из рюкзака, появляется на оружии в окне и в руках. Замена возвращает старую деталь в рюкзак.
7. «Крышка "Бастион"» снимает целик и крепления из своего списка `conflicts`; предупреждение об этом видно до установки.
8. Z возвращает прошлую сборку, Y повторяет, Backspace возвращает сборку на момент открытия.
9. Хоткеи окна не срабатывают в инвентаре и в игре, полоса внизу меняется после смены бинда.
10. Esc и кнопка-крестик закрывают окно, инвентарь под ним снова принимает ввод.
