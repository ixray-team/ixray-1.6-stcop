# Хоткеи: действия, контексты и подсказки

## Обзор

Одна система для всех клавиш интерфейса и игры:

1. **Действие** описывается один раз в `ltx`: где работает, клавиша по умолчанию, подпись, группа в меню управления.
2. **Контекст** определяет, где действие работает: `game`, `ui`, `pda`, `pda.map` и т.д. Контексты вложены друг в друга.
3. **Подсказки** рисуются из общего стиля: в разметке окна остаётся одна строка.
4. **Lua** может добавлять свои действия и ловить их нажатия без правок движка.

Встроенные действия движка (`ui_tab_left`, `pda_tasks_*` и все остальные) работают как раньше и тоже участвуют в системе. Бинды хранятся в `user.ltx` как обычно: `bind имя_действия клавиша`.

## Действие

Секция `[hotkey.<имя>]` в любом системном конфиге, например `configs/mod_system_my_addon.ltx`:

```ini
[hotkey.my_addon_scanner]
context  = game
key      = kJ
gamepad  = cY
label    = st_my_addon_scanner
options  = kb_grp_my_addon
hint     = 10
```

| Поле | Значение |
| --- | --- |
| `context` | Где работает действие. По умолчанию `game`. Для встроенных действий игнорируется. |
| `key`, `key2` | Основная и дополнительная клавиша по умолчанию |
| `gamepad`, `gamepad2` | Кнопки геймпада по умолчанию |
| `label` | Id строки подписи: в меню управления и в авто-полосе подсказок |
| `options` | Id строки группы в меню управления. Без него действие в меню не попадает. |
| `hint` | Порядок в авто-полосе подсказок, 0 — не показывать |

Секцию можно написать и для встроенного действия: тогда задаются только клавиши по умолчанию, подпись, группа и порядок. Например, HD HUD так выносит действия карты в меню управления.

Клавиши по умолчанию применяются командой `default_controls` (при запуске и кнопкой «По умолчанию» в настройках). Бинды игрока из `user.ltx` их перекрывают.

Всего можно добавить 256 своих действий.

## Контексты

| Контекст | Родитель | Где действует |
| --- | --- | --- |
| `game` | | В игре без открытого интерфейса |
| `game.vehicle`, `game.aiming` | `game` | Транспорт, прицеливание |
| `ui` | | Любое открытое окно |
| `pda` | `ui` | ПДА |
| `pda.map`, `pda.journal`, `pda.records`, `pda.reference`, `pda.contacts`, `pda.logs` | `pda` | Вкладки ПДА |

Свои контексты задаются секцией `[hotkey_contexts]`: `имя = родитель`.

```ini
[hotkey_contexts]
my_addon.menu = ui
```

Как работают:

1. Нажатие ищется сначала в активном контексте, потом в его родителях. Действие вкладки перекрывает действие ПДА на той же клавише.
2. Одна клавиша не может быть у двух действий одного контекста: при назначении она снимается со старого действия. В разных контекстах одна клавиша работает независимо.
3. Без открытого интерфейса активен `game`. Открытое окно включает свой контекст, остальные окна дают `ui`.

## Слои

Слои позволяют назначить одну клавишу на разные действия в разных окнах: F — «Использовать» в игре, «Вести к метке» на карте и «Отслеживать» в «Записях». Нажатие получает самый верхний слой, остальные — только то, что он не забрал.

Слои выключены по умолчанию. Без флага окна получают нажатия в прежнем порядке, всё работает как раньше.

```ini
[hotkey_layers]
enabled = true

[hotkey_layer.my_addon.menu]
parent   = ui
priority = 200
block    = all
label    = st_my_addon_menu_layer
```

| Поле | Значение |
| --- | --- |
| `parent` | Родительский контекст |
| `priority` | Чем больше, тем раньше слой получает нажатие. При равенстве первым идёт слой, включённый позже. |
| `block` | `all` — нажатие, которое слой не взял, не передаётся нижним слоям (старая обработка окна при этом работает). `none` (по умолчанию) — передаётся. У `ui` по умолчанию `all`: пока открыто окно, игровой слой нажатий не получает. Если поле не указано, остаётся прежнее значение слоя. |
| `label` | Id строки с названием слоя для меню управления, например «ПДА: записи». Без него слой в меню не подписывается. |

Приоритеты встроенных слоёв: `game` 0, `ui` 50, `pda` 100, вкладки ПДА 110.

Слои работают во всей игре, а не только в ПДА:

1. Слой `game` активен, пока загружен уровень.
2. Любое окно, открытое как диалог (инвентарь, торговля, разговор, ПДА, окна модов), включает свой корневой слой, по умолчанию `ui`. Окно может задать свой контекст.
3. Нажатие раздаётся только слоям верхнего окна и слоям, которые включились после него. Окно, открытое поверх другого, полностью перекрывает его слои: буквы в поле ввода не переключат вкладки ПДА под ним.
4. Внутри окна слои могут уточнять друг друга: ПДА обрабатывает `pda` и `ui` (вкладки Q/E), карта — `pda.map`, «Записи» — `pda.records`, «Журнал» — `pda.journal`.
5. Нажатие идёт по слоям от верхнего к нижнему. Слой берёт его, если на клавише есть действие из его контекстов и он его выполнил. Свои действия (Lua) срабатывают в тех слоях, где они видны.
6. Если ни один слой не взял нажатие, оно идёт старым путём.
7. Одна клавиша в разных контекстах — не конфликт. В меню управления конфликтом считается только совпадение внутри одного контекста.

Слой из C++: `CHotkeyContextScope` со `SetContext`, `SetHandler(контексты, обработчик)` и `SetActive`. У окна — `SetHotkeyContext` и `GetHotkeyLayer`.

Пример: E назначена на «Вкладку вправо» (`ui`) и «Действие» в «Записях» (`pda.records`). На вкладке «Записи» E выполняет действие, на остальных вкладках переключает вкладку.

### Меню управления

С включёнными слоями меню управления показывает, где работает каждая клавиша. Без флага меню остаётся прежним.

1. У действия, чей слой имеет `label`, к подписи добавляется название слоя: «Отслеживать  (ПДА: записи)».
2. Звёздочка после клавиши («F *») значит, что та же клавиша назначена в родственном слое — родительском или дочернем. Например, F в игре и F в «Записях». Это не ошибка: в окне сработает действие верхнего слоя, в игре — игровое.
3. Если назначить клавишу, которая уже занята в этом же слое, поле показывает «E? - Вкладка вправо». Повторное нажатие той же клавиши подтверждает замену, и клавиша снимается со старого действия. Другая клавиша или уход из поля отменяет замену.
4. Свои действия без `options`, у слоя которых есть `label`, собираются в группу с названием слоя.

HD HUD подписывает слои `ui`, `pda`, `pda.map`, `pda.journal`, `pda.records` и `pda.reference`.

На геймпаде вкладки ПДА по-прежнему переключает старый обработчик (с повтором при удержании). Слои вкладок работают и на геймпаде.

## Подсказки

### Стили

Файл `configs/ui/hotkey_styles.xml` содержит шаблоны плашек. Моды дополняют его файлом `mod_hotkey_styles_*.xml`.

```xml
<w>
	<style id="pda" key_padding="6" key_min_width="22" key_spacing="3" label_spacing="6" item_spacing="16">
		<key_back type="line" x="0" y="0" width="22" height="22">
			<texture>ui_RP2_HotKey</texture>
		</key_back>
		<key x="0" y="0" width="22" height="22">
			<text align="c" vert_align="c" font="font_rubik_12" r="225" g="225" b="225"/>
		</key>
		<label x="0" y="0" width="10" height="22">
			<text align="l" vert_align="c" font="font_rubik_12" r="190" g="190" b="190"/>
		</label>
	</style>
</w>
```

Атрибуты `key_back`, `key`, `label` и отступов описаны в [легенде карты](pda-map-legend-hotkeys.md#клавиши-плашки).

### Одна плашка

```xml
<hotkey x="252" y="39" width="22" height="22" chips_align="c" action="ui_tab_left" style="pda"/>
```

### Полоса

Явный список:

```xml
<hotkey_bar x="50" y="710" width="470" height="22" style="pda">
	<item action="pda_tasks_toggle_legend" label="pda_hint_legend"/>
	<item action="pda_tasks_map_zoom_in,pda_tasks_map_zoom_out">pda_hint_zoom</item>
</hotkey_bar>
```

Автоматически, все действия контекста с `hint > 0` по порядку `hint`:

```xml
<hotkey_bar x="50" y="710" width="900" height="22" style="pda" context="pda.map"/>
```

1. `context` принимает несколько контекстов через запятую. Явные пункты и авто-пункты можно смешивать, в авто-режиме не больше 16 пунктов.
2. Атрибуты самого узла перекрывают атрибуты стиля. Если внутри узла есть свой `key`, стиль не нужен.
3. Полоса обновляется сама при смене бинда, устройства ввода и при регистрации новых действий.
4. Действия без клавиши не показываются. Пункты, которые не влезают по ширине, убираются с конца.
5. Старый узел `hotkeys_hint` работает как `hotkey_bar`.

Узлы `hotkey`, `hotkey_bar` и `hotkeys_hint` понимают окна ПДА: `pda.xml`, `pda_tasks.xml`, `pda_task_journal.xml`, `pda_records.xml`, `pda_reference.xml`, панель личных меток.

## Lua

Модуль `hotkeys`:

```lua
function on_game_start()
	hotkeys.register("my_addon.scanner", {
		context = "game",
		key = "kJ",
		gamepad = "cY",
		label = "st_my_addon_scanner",
		options = "kb_grp_my_addon",
		hint = 10,
	})
	hotkeys.on("my_addon.scanner", function(name)
		my_addon.toggle_scanner()
	end)
end
```

| Функция | Что делает |
| --- | --- |
| `register(name, def)` | Регистрирует действие. `def` — те же поля, что в `ltx`. Клавиши применяются, только если действие ещё не назначено. |
| `register_context(name, parent)` | Добавляет контекст |
| `register_layer(name, def)` | Добавляет слой: `parent`, `priority`, `block` |
| `layers_enabled()` | Включены ли слои |
| `on(name, fn)`, `off(name, fn)` | Подписка на нажатие. `fn(name)` может вернуть `false`, чтобы не поглощать нажатие. |
| `push_context(name)`, `pop_context(name)` | Включить и выключить свой контекст, например для своего меню |
| `active_context()` | Текущий контекст |
| `key_name(name)` | Текст клавиши для текущего устройства: `J` или `Y` |
| `is_bound(name)` | Назначена ли клавиша |
| `context_of(name)` | Контекст действия |
| `action_at(dik, context)` | Какое действие на клавише в контексте, по умолчанию в текущем |

1. `hotkeys.on` получает нажатия только своих действий. Встроенные действия обрабатывает движок.
2. Обработчик срабатывает, только когда действие видно из активного контекста.
3. Действие, зарегистрированное из Lua, сохраняет бинд игрока: строка `bind` из `user.ltx` запоминается и применяется при регистрации. Для клавиш по умолчанию и пункта в меню управления надёжнее секция `ltx`: она есть ещё до загрузки скриптов.
4. В тексте строк по-прежнему работает `$$ACTION_имя$$`, в том числе для своих действий.

## Ограничения

1. Своих действий не больше 256.
2. Свёрнутые и временные контексты не сохраняются: окно включает свой контекст при каждом показе.
3. Подсказки и контексты пока подключены только в окнах ПДА. Другие окна дают общий контекст `ui`.
4. Обработчики Lua работают только на уровне: в главном меню нажатия до них не доходят.

## Проверка после сборки

1. Q и E у вкладок ПДА и полосы хоткеев на карте показывают клавиши, после смены бинда в настройках обновляются без перезапуска.
2. В меню управления есть группа «ПДА: карта» с действиями карты и их клавишами.
3. Действие из `[hotkey.*]` с `key` получает клавишу после «По умолчанию» в настройках и сохраняется в `user.ltx`.
4. `hotkeys.register` и `hotkeys.on` из Lua: нажатие вызывает обработчик в игре, а при открытом ПДА не вызывает, если контекст `game`.
5. `<hotkey_bar context="pda.map"/>` показывает действия карты с `hint` по порядку.
6. Встроенные действия ведут себя как раньше: переключение вкладок, управление картой, «Записи» и «Журнал».
7. Без `[hotkey_layers] enabled` на вкладке «Записи» E переключает вкладку, как раньше. С флагом E выполняет действие записи, Q/E на остальных вкладках переключают вкладки.
8. Одна клавиша в двух разных слоях назначается в меню управления без очистки другого поля.
9. С HD HUD в меню управления у действий карты и «Записей» видно название слоя, у F в игре и в «Записях» стоит звёздочка.
10. Назначение E на действие слоя `ui`, где E уже занята, сначала показывает «E? - ...», второе нажатие E подтверждает, нажатие другой клавиши отменяет.
11. После «По умолчанию» и после смены бинда звёздочки обновляются без повторного открытия меню.
12. Без `[hotkey_layers] enabled` подписи, звёздочки и подтверждение не появляются, занятая клавиша снимается со старого действия сразу.
