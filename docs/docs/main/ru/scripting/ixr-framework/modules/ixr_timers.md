
# IXR Framework (LUA Фреймворк)
> [!IMPORTANT]
> **Статус**: Поддерживается<br>
> **Минимальная версия**: 1.4.0

## Модуль таймеров IXR TIMERS
Позволяет создавать хранимые в сохранениях игры таймеры с полезной нагрузкой в виде скрипт функции которая будет выполнена по истичении таймера.

Объект обычного таймера `TimerCreate` записывается в сохранение игры. Для технических задач и главного меню предусмотрено отдельное семейство HighLoad без сохранения состояния (см. ниже).

```lua
--// Создать таймер
TimerCreate(name, loop, auto_play, left_milliseconds, callable_fn, ...)
args: 
  name (string)(required) - уникальное имя таймера.
  loop (bool)(required) - флаг циклического повтора.
  auto_play (bool)(required) - флаг автоматического запуска.
  left_milliseconds (int)(required) - время до срабатывания в миллисекундах.
  callable_fn (function)(...) - функция вызываемая по окончании таймера (принимает аргументы переданные как ...).
  ... (аргументы для callable_fn функции)

retval: (table) возвращаемые как ООП методы созданного таймера
	self:name(): string - получить имя таймера.
	self:exists(): bool - проверить существование таймера.
	self:play(): bool - запустить таймер.
	self:stop(): bool - остановить таймер.
	self:delete(): bool - удалить таймер.

--// Проверить существование таймера по имени
IsTimerExists(name)
args: 
  name (string)(required) - уникальное имя таймера.
retval: (bool) возвращаемые true если таймер существует иначе false

--// Запуск таймера по имени (игнорируется если таймера нет или он уже запущен)
TimerPlay(name)
args: 
  name (string)(required) - уникальное имя таймера.
retval: (bool) возвращаемые true если таймер запустился иначе false

--// Остановка таймера по имени (игнорируется если таймера нет или он еще не запущен)
TimerStop(name)
args: 
  name (string)(required) - уникальное имя таймера.
retval: (bool) возвращаемые true если таймер остановлен иначе false

--// Удаление таймера по имени (игнорируется если таймера нет)
TimerDelete(name)
args: 
  name (string)(required) - уникальное имя таймера.
retval: (bool) возвращаемые true если таймер удален иначе false
```

### HighLoad: таймеры без сохранения

HighLoad-таймеры хранятся отдельно в `ixr_timers.dynamic_vars.highload_timers`; сохранение и восстановление обычных таймеров их не затрагивает. Они обновляются через `on_frame`, используют `device().dwtime_continual` в миллисекундах и не требуют актора или работающего игрового времени. Поэтому они подходят для главного меню во время игровой паузы. При отсутствии таймеров обработчик возвращается до чтения времени.

```lua
--// Создать лёгкий таймер без сохранения.
CreateHighLoadTimer(name, loop, auto_start, milliseconds, callable_fn, ...)
args:
  name (string)(required) - непустое имя HighLoad-таймера, уникальное внутри вызывающего скрипта.
  loop (bool)(optional) - повторять таймер; nil или неверный тип заменяется на false (одноразовый).
  auto_start (bool)(optional) - начать отсчёт сразу; nil или неверный тип заменяется на true. Явный false создаёт остановленный таймер.
  milliseconds (number)(optional) - конечный положительный интервал в миллисекундах. nil, неверный тип, NaN, бесконечность, ноль или отрицательное число заменяются на 50 мс.
  callable_fn (function)(required for a new timer) - обработчик с сигнатурой callable_fn(...). Для уже существующего имени можно не передавать.
  ... - аргументы обработчика; nil сохраняются, таблицы передаются по ссылке.
retval: (table|false) - таблица методов таймера, как у TimerCreate:
  self:name(): string - имя таймера.
  self:exists(): bool - существует ли таймер.
  self:play(): bool - запустить или продолжить отсчёт.
  self:stop(): bool - остановить с сохранением оставшегося времени.
  self:delete(): bool - удалить таймер.
  false - неверное имя, отсутствует корректный обработчик нового таймера или модуль недоступен.

--// Проверить наличие запущенного или остановленного таймера.
ExistsHighLoadTimer(name)
args:
  name (string)(required) - имя HighLoad-таймера внутри вызывающего скрипта.
retval: (bool) - true, если таймер существует; иначе false.

--// Запустить или продолжить отсчёт оставшегося времени.
StartHighLoadTimer(name)
args:
  name (string)(required) - имя HighLoad-таймера внутри вызывающего скрипта.
retval: (bool) - true, если запущен; false, если отсутствует, уже запущен или модуль недоступен.

--// Остановить отсчёт, сохранив оставшееся время.
StopHighLoadTimer(name)
args:
  name (string)(required) - имя HighLoad-таймера внутри вызывающего скрипта.
retval: (bool) - true, если остановлен; false, если отсутствует, уже остановлен или модуль недоступен.

--// Удалить таймер и освободить ссылки на обработчик и аргументы.
DeleteHighLoadTimer(name)
args:
  name (string)(required) - имя HighLoad-таймера внутри вызывающего скрипта.
retval: (bool) - true, если удалён; false, если отсутствует или модуль недоступен.
```

Для пропуска необязательных позиционных параметров передай `nil`: `CreateHighLoadTimer("example.once", nil, nil, nil, on_timer)` создаёт одноразовый таймер с автоматическим запуском через 50 мс. `name` обязателен, `callable_fn` обязателен только при создании нового таймера. Если имя уже существует в этом скрипте, возвращается новая таблица замыканий на него, а параметры, обработчик и состояние существующего таймера сохраняются. Методы привязаны к паре «скрипт создателя + имя»; поддерживают вызовы через точку и двоеточие. Значения по умолчанию применяются при создании; дополнительных проверок аргументов в покадровом обработчике нет.

Все пять глобальных функций определяют вызывающий скрипт через `ffx_callable_utils.find_caller_source(3)`. Одинаковые имена в разных скриптах создают независимые таймеры; глобальные операции по имени затрагивают только таймер своего скрипта. Возвращённая таблица методов сохраняет контекст создателя: её можно передать другому скрипту и управлять исходным таймером. Определение скрипта выполняется при вызове глобального API, а не покадрово. На границе модуля аргумент `caller_script_name` передаётся перед `name`; прикладной код использует глобальные обёртки.

`highload_timers` — плотный массив записей с явными полями `caller_script_name`, `name` и `index`. Пустота проверяется через `#highload_timers == 0`. При удалении последняя запись переносится на освободившееся место без сдвига остальных; порядок вызовов не является контрактом.

`IXRLog` фиксирует создание, успешный запуск, остановку и явное удаление HighLoad-таймера с именем его скрипта. Покадровое обновление, срабатывания и автоматическое удаление одноразового таймера не логируются.

Проверки прикладных условий в модуле нет. Состояние владельца передавай таблицей через `...`: обработчик получит ту же ссылку и сможет прочитать актуальные поля **только при срабатывании**. При временном скрытии UI вызывай `StopHighLoadTimer`, при повторном показе — `StartHighLoadTimer`; остановленный таймер не уменьшает оставшееся время и не вызывает обработчик. Перед окончательным удалением владельца вызови `DeleteHighLoadTimer`.

Обработчик выполняется синхронно при истечении интервала; его результат игнорируется. Поддерживаются замыкания и аргументы по ссылке. Одноразовый таймер удаляется **до** вызова обработчика, поэтому внутри можно создать новый с тем же именем. Циклический срабатывает не чаще одного раза за кадр: пропущенные при задержке кадра вызовы не догоняются, новый интервал отсчитывается от текущего кадра. Порядок одновременных срабатываний не определён. Обработчик может удалять и останавливать другие таймеры; отменённые вызовы из того же кадра пропускаются. Ошибки пользовательских функций не перехватываются.

Имена HighLoad не пересекаются с именами `TimerCreate`. Модуль не удаляет их при загрузке игрового сейва: их жизненным циклом управляет вызывающий код, до удаления или завершения Lua-состояния. При недоступном модуле все пять глобальных функций возвращают `false`. Обычные `TimerCreate`/`TimerPlay`/`TimerStop` сохраняют прежнее поведение.

```lua
function create_menu_timer(state)
	CreateHighLoadTimer("example.menu.refresh", true, true, 100, update_menu_timer, state)
end

function update_menu_timer(state)
	if not state.visible then return end
	refresh_menu(state.ui)
end

function remove_menu_timer()
	DeleteHighLoadTimer("example.menu.refresh")
end
```

`state` — таблица владельца с актуальными полями `visible` и `ui`; `refresh_menu(ui)` — прикладной обработчик примера. Создавай таймер один раз для владельца, удаляй перед окончательным удалением UI. Для ограничения частоты внутри уже существующего update достаточно [IXR Throttler](./ixr_module_throttlers.md).

### Примеры:
```lua

--// выставляем ожидание события новой игры
function on_game_start(callbackRegistrator)
	RegisterScriptCallback("new_game_created", this.on_new_game_started)
end

function on_new_game_started()
  --// здесь можно определить таймеры как вариант в начале новой игры
end

--// Автоматически запустится и будет повторяться каждые 5 секунд.
TimerCreate
(
  "my-timer-01", true, true, 5000, 
  function (a, b) 
    ...
  end, 
  "Переменная А", "Переменная Б"
 )

--// Автоматически запустится и сработает единожды через 5 секунд.
TimerCreate
(
  "my-timer-02", false, true, 5000, 
  function (a, b) 
    ...
  end, 
  "Переменная А", "Переменная Б"
 )

 --// Создаем таймер который сработает единожды через 5 секунд но он не запущен сразу после создания (запускаем его позже по мере необходимости - позволяет делать сложные отложенные цепочки действий т.к таймеры можно вкладывать друг в друга).
TimerCreate
(
  "my-timer-02", false, false, 5000, 
  function (a, b) 
    ...
  end, 
  "Переменная А", "Переменная Б"
 ):play()


--// Проверить существование таймера по имени
if IsTimerExists("my-timer-02") then
  ...
end

--// Запуск таймера по имени
TimerPlay("my-timer-02")

--// Остановка таймера по имени
TimerStop("my-timer-02")

--// Удаление таймера по имени
TimerStop("my-timer-02")
```
