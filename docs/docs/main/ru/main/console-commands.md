# Консольные команды

> [!IMPORTANT]
> **Статус**: Поддерживается<br>
> **Минимальная версия**: 1.4

## Обзор

Введите `help` в консоли, чтобы получить список команд, текущие значения и сведения об аргументах для запущенной сборки. Список зависит от рендерера, режима игры и флагов сборки. Команды, зарегистрированные модом или при первом обращении к настройке, появляются после регистрации.

Для переключателей в этом справочнике используйте `1` и `0`. Такую запись принимают и булевы команды, и битовые флаги. У некоторых команд без аргумента выводится текущее значение.

## Синтаксис

```text
r__screenshot_format ss_png
screenshot test
rs_main_menu_fps_limit 60
```

## Экран и рендеринг

| Команда | Значения | Действие |
| --- | --- | --- |
| `rs_fps_limit` | `0–1000` | Лимит FPS во время игры, `0` снимает лимит. |
| `rs_main_menu_fps_limit` | `0–1000` | Отдельный лимит для главного меню. Исходное значение `144`, `0` снимает лимит. |
| `rs_fps_show` | `0 / 1` | Показывает счётчик FPS. |
| `rs_fps_color_r`, `rs_fps_color_g`, `rs_fps_color_b`, `rs_fps_color_a` | `0–255` | Цвет и непрозрачность счётчика. |
| `rs_fps_outline` | `0 / 1` | Обводка счётчика FPS. |
| `r__detail_density` | `0.25–1.0` | Плотность деталей. На загруженном уровне команда также обновляет кэш деталей. |
| `r__detail_radius` | `50–500` | Радиус отрисовки деталей. |
| `r__shader_cache` | `0 / 1` | Переключает использование кэша шейдеров. |
| `r2_vignette`, `r2_aberration`, `r2_saturation` | `on / off` | Виньетка, хроматическая аберрация и коррекция насыщенности в проходе постобработки R2/R4. |
| `r2_cloud_shadows` | `on / off` | Тени облаков в R2/R4. Для применения перезапустите рендерер. |
| `r4_hud_shadows` | `on / off` | Экранные тени HUD в R4. |
| `r4_sslr_water`, `r4_sslr_reflections` | `on / off` | Отражения в R4 для воды и геометрии сцены соответственно. |
| `r4_vslr_enable` | `on / off` | Включает путь отражений геометрии за пределами экрана в R4. |
| `r2_sun_hom` | `0 / 1` | Разрешает HOM-отсечение для прохода солнца, когда рендерер может подготовить HOM. Имя команды общее для динамических рендереров. |
| `r__screenshot_format` | `ss_jpg / ss_tga / ss_png` | Формат обычного скриншота. Исходное значение `ss_png`. |
| `screenshot` | `name` | Сохраняет скриншот с указанным именем в клиенте. |

## Назначение на клавишу

`bind_console <команда> <клавиша>` сохраняет привязку. Последний токен является именем клавиши, например `kF10`. Для bool и битовых флагов обработчик нажатия инвертирует текущее значение. `unbind_console <клавиша>` снимает привязку.

```text
bind_console rs_fps_show kF10
unbind_console kF10
```

## Регистрация из Lua

`get_console():register_lua_command(name, handler, tips)` регистрирует команду. Обработчик получает таблицу аргументов с индексами от 1. Разделитель аргументов и подсказок — запятая. Используйте уникальное имя мода. Повторная регистрация Lua-команды обновляет обработчик и подсказки. Встроенные команды зарезервированы. После пересоздания Lua VM мод регистрирует свои команды заново.

```lua
local console = get_console()
console:register_lua_command("my_mod_echo", function(args)
    printf("%s / %s", args[1] or "", args[2] or "")
end, "first,second")
-- В консоли: my_mod_echo first,second
```
