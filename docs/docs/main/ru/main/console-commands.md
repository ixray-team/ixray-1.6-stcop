# Консольные команды

## Спавн объектов с масштабом

`g_spawn_scaled <секция> <скейл>` создаёт один объект под прицелом в одиночной игре.
Диапазон масштаба команды: `0.01`–`100`; `1` — исходный размер, `0.5` — половина, `2` — двойной размер.
Например: `g_spawn_scaled dog_normal 0.5` или `g_spawn_scaled stalker 1.5` (секция должна существовать в текущей сборке).

Для NPC и монстров масштабируются скелет, вершины тела, смещения анимаций, анимационное перемещение,
костные шейпы попаданий и физики (box, sphere, cylinder), их центры и размеры, а также боксы передвижения.
Скорости ходьбы и бега умножаются на `sqrt(scale)`: размер 4 даёт скорость ×2, размер 0.25 — ×0.5.
Планировщик использует тот же коэффициент. Сам размер не ускоряет и не замедляет анимационные клипы.
Атакующие анимации не ускоряются и не перезапускаются из-за изменения размера.
Дальность и допустимая высота прыжков остаются заданными конфигом. Дистанции ближней атаки и
объём проверки прыжка учитывают размер; при масштабе 1 сохраняется исходная проверка прыжка.
Физическое время прыжка рассчитывается по реальной точке приземления, без повторного умножения на масштаб.
Масса и игровые характеристики остаются заданными конфигом.
Масштабированные экземпляры используют полную модель вместо отдельного нескелетного LOD.

Параметр `visual_scale = 1.0` в секции задаёт исходный масштаб ALife-объекта.

Для предметов, NPC и мутантов `visual_scale = 1.0` задаёт фиксированный масштаб,
а `visual_scale = 0.3, 1.3` выбирает случайный масштаб нового ALife-объекта.
Без параметра или при пустом значении используется 1.0. Допустимы одно или два
числа в пределах 0.01–100; для диапазона первое не должно превышать второе.
Ошибочное значение оставляет 1.0 и выводит предупреждение в лог.
Явный масштаб спавна и значение из сохранения приоритетнее, включая сохранённый 1.
Повторный выход в онлайн не меняет размер; новые настройки не перерандомизируют
уже сохранённые объекты. Отдельные ключи visual_scale_min/max больше не используются.
Масштабирование использует существующий механизм скелетных визуалов; это не меняет
размер иконки, HUD-модели оружия или произвольного нескелетного визуала.

Команда переопределяет его только у создаваемого экземпляра, без изменения OGF, OMF или секции.
В Lua серверный параметр доступен как `alife_object.visual_scale`; присваивание проверяется и
для online-объекта передаётся клиентскому экземпляру.

Индивидуальный масштаб передаётся в spawn NET_Packet и сохраняется в обоих форматах сохранений.
Он сохраняется при загрузке и переходах online/offline. Версия spawn-пакета — 135;
старые данные читаются с масштабом из секции (по умолчанию 1).


## Рост и уменьшение из Lua

У `game_object` и серверного ALife-объекта доступны `get_visual_scale()` и `set_visual_scale(scale)`.
Сеттер возвращает `true` при успехе, `false` при недопустимом значении или неподдерживаемом состоянии.
Допустимы положительные значения `0.01`–`100`; рекомендуемый игровой диапазон — примерно `0.5`–`3`.
Отрицательное направление изменения означает уменьшение положительного коэффициента, например `2` → `0.5`.

Пример вызова раз в 100 мс (`dt` — прошедшее время в секундах):

```lua
local next_scale = math.min(3, obj:get_visual_scale() + 0.02 * dt)
local applied = obj:set_visual_scale(next_scale)
```

Сеттер не перезапускает логику и клипы, не сбрасывает фазу атаки. Кости обновляются на месте;
после первого изменения повторные выделения памяти для их копий не требуются.
Физическое тело сохраняет нижнюю опорную точку и скорость, включая историю интерполяции.
Изменение во время анимационного перемещения учитывает текущую фазу и сохраняет позицию объекта.
Для моделей с IK обновляются длины сегментов и локальная геометрия стоп без пересоздания контроллера.
Для активного ragdoll или анимационного physics shell изменение отклоняется: проверяйте результат и
повторяйте вызов при следующем обновлении роста. Объект хранит успешно присвоенный скейл в сохранении.

Навигационный коэффициент равен `max(1, scale)`: уменьшение до `0.1` не уменьшает исходные
навигационные зазоры. Радиусы планируемых поворотов и локальные манёвры крупных монстров увеличиваются,
а скорость движения изменяется по `sqrt(scale)`. Малые изменения цели сохраняют текущий путь. Изменение
навигационного коэффициента на 2% относительно последнего обновления помечает путь для перестроения.
Сеттер не запускает поиск пути или проверки всей геометрии карты синхронно.
Это не заменяет полноценный поиск проходов для увеличенного физического объёма.

Начало ближней атаки и проверка попадания используют один расчёт дистанции. Он учитывает
скейл атакующего и горизонтальный габарит цели с её ориентацией; маленькому монстру не требуется
подойти внутрь коллизии крупной цели, а большая модель не получает лишнюю дальность из-за маленькой цели.
В конфигурации `visual_scale = 1.0` задан в `[monster_base]` и `[stalker]`; дочерние секции наследуют его.

Навигационные зазоры при уменьшении не сужаются. Допуск достижения конечной точки и контроль
продвижения учитывают маленький размер; время локального перемещения увеличивается при снижении скорости.
Наземное преследование масштабированной пары не останавливается только из-за совпадения ячейки AI-сетки.
