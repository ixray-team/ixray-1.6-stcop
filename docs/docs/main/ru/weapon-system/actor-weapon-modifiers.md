# Модификаторы оружия актора

[English version](/en/weapon-system/actor-weapon-modifiers)

Модификаторы позволяют из Lua менять урон, скорострельность, меткость и другие характеристики оружия актора без перезаписи конфигурации оружия и значений улучшений. Все коэффициенты изначально равны **`1.0`**. Они принадлежат актору и применяются к его оружию в **одиночной игре**.

Значение `1.20` означает множитель 1,2, а не прибавку 1,2. Для разброса, инерции и отдачи уменьшение коэффициента улучшает характеристику. Это значения времени выполнения, а не параметры оружейной секции LTX.

## Быстрый старт

Выполняйте код при выдаче или изменении бонуса, когда актор уже существует. Проверка также позволяет безопасно пропустить вызовы на старом движке без этого API.

```lua
local actor = db.actor
if not actor or not actor.weapons_modifiers then
    return
end

local damage = actor:weapons_modifiers(weaponsModifiers.HIT_POWER_COEFF)
local recoil = actor:weapons_modifiers(weaponsModifiers.RECOIL_COEFF)

assert(actor:weapons_modifiers(weaponsModifiers.HIT_POWER_COEFF, 1.20))
assert(actor:weapons_modifiers(weaponsModifiers.RECOIL_COEFF, 0.75))
```

У метода две формы:

| Вызов | Результат |
| --- | --- |
| `actor:weapons_modifiers(modifier)` | Текущий коэффициент в виде числа. |
| `actor:weapons_modifiers(modifier, value)` | Устанавливает абсолютное значение; возвращает `true` при успехе и `false` при отказе. |

Передавайте модификатор константой из `weaponsModifiers`. Строковые имена не поддерживаются; используйте символические константы вместо числовых ID. Повторная установка одного значения не накапливает бонус. Для строкового вызова больше нет подходящей перегрузки Lua; такой вызов не является отклонённым сеттером, возвращающим `false`.

## Справочник коэффициентов

| Enum в `weaponsModifiers` | Действие |
| --- | --- |
| `HIT_POWER_COEFF` | Общий множитель урона пули. |
| `RPM_COEFF` | Скорострельность: увеличение сокращает интервал между выстрелами. |
| `SILENCER_HIT_POWER_COEFF` | Дополнительный множитель урона при стрельбе с глушителем. |
| `UNSILENCED_HIT_POWER_COEFF` | Дополнительный множитель урона при стрельбе без глушителя. |
| `HIT_IMPULSE_COEFF` | Импульс попадания, передаваемый цели и влияющий на отлёт тела. |
| `FIRE_DISPERSION_BASE_COEFF` | Базовый разброс оружия: уменьшение повышает меткость. |
| `CROSSHAIR_INERTION_COEFF` | Инерция сведения прицела: уменьшение ускоряет сведение. |
| `BULLET_SPEED_COEFF` | Начальная скорость пули, влияющая на настильность траектории. |
| `RECOIL_COEFF` | Сила вертикального и горизонтального толчка отдачи: уменьшение ослабляет подброс. |

Сеттер один раз вызывает `clamp(Value, 0.001f, FLT_MAX)` перед записью коэффициента. Значения ниже `0.001`, включая ноль и отрицательные значения, превращаются в `0.001`; значения выше `FLT_MAX`, включая положительную бесконечность, — в `FLT_MAX`. Штатный clamp не нормализует NaN; вызывающий код не должен передавать NaN. Неверные ID enum и вызовы на объектах, не являющихся актором, отклоняются с записью в лог; ошибочный геттер возвращает `1.0`.

Минимальный коэффициент — `0.001`: соответствующая составляющая уменьшается до одной тысячной, а не отключается. В обычном пути стрельбы разброс актора добавляется отдельно; специальный режим базового разброса первых выстрелов очереди его не добавляет.

## Примеры использования

Следующие фрагменты — независимые рецепты. Выполняйте их, когда `db.actor` и API доступны, как проверено в быстром старте. Они меняют только указанные параметры; остальные действующие коэффициенты сохраняются. Подбирайте значения под свой мод, а не применяйте все рецепты одновременно.

### Урон с глушителем и без него

```lua
local actor = db.actor
actor:weapons_modifiers(weaponsModifiers.HIT_POWER_COEFF, 1.20)
actor:weapons_modifiers(weaponsModifiers.SILENCER_HIT_POWER_COEFF, 1.10)
actor:weapons_modifiers(weaponsModifiers.UNSILENCED_HIT_POWER_COEFF, 1.05)
```

Итоговый множитель актора: `HIT_POWER_COEFF × выбранный_коэффициент_урона`. По режиму стрельбы выбирается ровно один дополнительный коэффициент; встроенный глушитель тоже учитывается. В этом примере множитель актора равен `1.32` с глушителем и `1.26` без него. Установку и снятие глушителя обрабатывает движок.

При текущем уроне после улучшений `0.70` результат до штатных множителей глушителя и патрона составит `0.924` и `0.882`. Коэффициент применяется к текущему урону выбранного уровня сложности, а не к сохранённой копии исходного урона. Скрипты отображения характеристик должны использовать ту же формулу.

### Настройки для точной стрельбы

```lua
local actor = db.actor
actor:weapons_modifiers(weaponsModifiers.FIRE_DISPERSION_BASE_COEFF, 0.80)
actor:weapons_modifiers(weaponsModifiers.CROSSHAIR_INERTION_COEFF, 0.75)
actor:weapons_modifiers(weaponsModifiers.BULLET_SPEED_COEFF, 1.20)
actor:weapons_modifiers(weaponsModifiers.RECOIL_COEFF, 0.50)
```

Пример уменьшает базовый разброс оружия на 20%, ускоряет сведение прицела, увеличивает начальную скорость пули на 20% и ослабляет отдачу. В обычном пути стрельбы дополнительный разброс актора от движения считается отдельно; специальный режим первых выстрелов очереди использует только изменённый базовый разброс оружия. В одиночной игре сведение управляет индикатором прицела и не задерживает расчёт разброса пули.

### Повышенная скорострельность ценой урона

```lua
local actor = db.actor
actor:weapons_modifiers(weaponsModifiers.RPM_COEFF, 1.25)
actor:weapons_modifiers(weaponsModifiers.HIT_POWER_COEFF, 0.90)
```

Исходные `600 выстр./мин` превращаются в `750 выстр./мин`: интервал `0.10 / 1.25 = 0.08` секунды. Коэффициент действует в путях стрельбы из магазина и патронника, а также на отдельные интервалы одиночного выстрела и первых выстрелов очереди. Длительность перезарядки и анимации помпы не сокращается.

При `RPM_COEFF`, отличном от `1.0`, корректный рассчитанный интервал ограничивается снизу значением **1 мс**. Это ограничение интервала таймера, а не общий предел в 1000 пуль в секунду: один выстрел может выпускать несколько дробин, а путь стрельбы двустволки — расходовать два патрона за одну итерацию. Фактический темп также зависит от пути стрельбы, длительности кадра и состояния оружия. Нейтральный коэффициент точно сохраняет исходный интервал, включая необычно короткие интервалы из конфигурации.

### Импульс, передаваемый цели

```lua
local actor = db.actor
actor:weapons_modifiers(weaponsModifiers.HIT_IMPULSE_COEFF, 1.50)
-- Use 0.001 for the minimum impact impulse coefficient.
-- This does not change RECOIL_COEFF or HIT_POWER_COEFF.
```

Это импульс попадания, а не отдача оружия. Сохраняются штатные множители импульса глушителя и патрона. Фактическое перемещение тела зависит также от физики, места попадания и самой цели.

### Ограничение назначаемого значения

```lua
local actor = db.actor
assert(actor:weapons_modifiers(weaponsModifiers.RPM_COEFF, -1.0))
assert(math.abs(actor:weapons_modifiers(weaponsModifiers.RPM_COEFF) - 0.001) < 1e-8)

assert(actor:weapons_modifiers(weaponsModifiers.RECOIL_COEFF, -1.0))
assert(math.abs(actor:weapons_modifiers(weaponsModifiers.RECOIL_COEFF) - 0.001) < 1e-8)
```

Значения за пределами числового диапазона ограничиваются, а не отклоняются. Если вычисленный интервал выстрелов или скорость пули не представимы допустимым числом, используется исходное значение.

### Сброс одного коэффициента или всех настроек

```lua
local actor = db.actor
actor:weapons_modifiers(weaponsModifiers.RECOIL_COEFF, 1.0)

-- Full reset: use only when this script owns the entire profile.
local modifiers = {
    weaponsModifiers.HIT_POWER_COEFF, weaponsModifiers.RPM_COEFF,
    weaponsModifiers.SILENCER_HIT_POWER_COEFF, weaponsModifiers.UNSILENCED_HIT_POWER_COEFF,
    weaponsModifiers.HIT_IMPULSE_COEFF, weaponsModifiers.FIRE_DISPERSION_BASE_COEFF,
    weaponsModifiers.CROSSHAIR_INERTION_COEFF, weaponsModifiers.BULLET_SPEED_COEFF, weaponsModifiers.RECOIL_COEFF,
}
for _, modifier in ipairs(modifiers) do
    actor:weapons_modifiers(modifier, 1.0)
end
```

Отдельного метода сброса всех значений нет. Полный сброс может затереть эффекты другой системы; скрипт, управляющий только отдачей, должен сбрасывать только `RECOIL_COEFF`.

### Сочетание нескольких источников бонуса без повторного накопления

Храните множитель каждого источника под постоянным ID и заново вычисляйте произведение. Тогда изменение или удаление одного источника сохраняет действие остальных.

```lua
local damage_sources = {}

function set_damage_source(id, coefficient)
    damage_sources[id] = coefficient
    local combined = 1.0
    for _, value in pairs(damage_sources) do
        combined = combined * value
    end

    local actor = db.actor
    if actor and actor.weapons_modifiers then
        actor:weapons_modifiers(weaponsModifiers.HIT_POWER_COEFF, combined)
    end
end

set_damage_source("training", 1.20)
set_damage_source("equipment", 1.10) -- 1.32
set_damage_source("training", 1.20) -- Still 1.32
set_damage_source("temporary", 1.25) -- 1.65
set_damage_source("temporary", nil) -- Back to 1.32
```

Не читайте текущий коэффициент с последующим умножением на один и тот же бонус при каждом обновлении: так бонус накапливается с каждым вызовом. За итоговый коэффициент должен отвечать один координатор. Сеттер заменяет значение и не хранит сведения об источниках.

Итоговый коэффициент урона сохраняется движком, но таблица `damage_sources` из примера существует только в памяти Lua и автоматически не сохраняется. После загрузки восстановите таблицу из сохранённого состояния заданий, экипировки и эффектов до изменения отдельных источников; иначе следующее изменение источника заменит загруженное произведение неполным набором бонусов. При завершении временного эффекта вызывайте ту же функцию удаления его источника.

## Сохранение и загрузка

Движок сохраняет итоговые значения всех девяти коэффициентов вместе с актором. Успешный сеттер меняет текущий сеанс; следующее сохранение игры записывает это значение. При загрузке коэффициенты восстанавливаются до загрузки Lua binder'а актора. Отдельный обработчик сохранения и загрузки Lua только ради этих значений не нужен.

В сохранение записываются ровно девять последовательных значений `float` (36 байт) в порядке enum `WeaponModifier`, непосредственно в `CActor::save` и `CActor::load`. Сигнатуры и количества коэффициентов нет. У нового актора все коэффициенты равны `1.0`; при загрузке записанные значения присваиваются напрямую.

Сохранения без этих девяти значений и сохранения прежнего формата с сигнатурой и количеством несовместимы. Миграция старых сохранений не поддерживается; для этого формата нужна новая игра. Изменение количества или порядка коэффициентов меняет формат сохранения.

Проверка наличия метода определяет доступность Lua API, но не поддержку сохранения: ранние сборки предоставляли `weapons_modifiers` без сериализации значений. В скриптах с прежним строковым синтаксисом замените первый аргумент соответствующей константой `weaponsModifiers.*`.

Движок хранит итоговые коэффициенты, а не источники бонусов, таймеры или владельцев эффектов. Временный коэффициент остаётся в сохранении, пока скрипт его не изменит. Состояние срока действия эффекта сохраняйте отдельно; при завершении эффекта удаляйте или пересчитывайте его вклад.

## Постоянный бонус через события

Коэффициенты изначально равны `1.0` и **сохраняются и загружаются вместе с актором**. Обработчик ниже меняет коэффициенты при выдаче инфопорции обучения. При загрузке сохранения они восстанавливаются из пакета актора без вызова этого обработчика. Обход инвентаря, опрос каждый кадр и проверка инфопорции на каждом выстреле не требуются.

Полный пример ниже управляет только общим уроном и отдачей. При вызове `refresh()` назначаются `1.20` к урону и `0.80` к отдаче, если инфопорция обучения есть, либо `1.0` для обоих коэффициентов, если её нет. Само отсутствие инфопорции не вызывает обработчик и не сбрасывает загруженные коэффициенты.

1. Сохраните код ниже под именем `actor_weapon_modifiers.script` в каталоге `scripts/` своего мода.
2. Замените `example_weapon_training` на объявленную в моде инфопорцию или объявите этот ID в XML-файле, зарегистрированном в секции `[info_portions]` файла `configs/system.ltx`.
3. Используйте IX-Ray Framework с `RegisterScriptCallback` и `actor_on_info_callback`, затем полностью перезапустите игру для повторного поиска скриптов.
4. Выдайте инфопорцию из логики задания для применения бонуса. Последующие сохранения игры сохранят назначенные коэффициенты.

```lua
-- Install in your mod's scripts directory; IX-Ray Framework loads on_game_start.
-- Replace this ID with an infoportion declared by your mod.
local TRAINING_INFO = "example_weapon_training"
local registered = false

function refresh()
    local actor = db.actor
    if not actor or not actor.weapons_modifiers then
        return
    end

    local damage = 1.0
    local recoil = 1.0
    if actor:has_info(TRAINING_INFO) then
        damage = 1.20
        recoil = 0.80
    end

    -- Assign an absolute coefficient: repeated events must not compound the bonus.
    actor:weapons_modifiers(weaponsModifiers.HIT_POWER_COEFF, damage)
    actor:weapons_modifiers(weaponsModifiers.RECOIL_COEFF, recoil)
end

local function on_actor_info(npc, info_id)
    if info_id == TRAINING_INFO then
        refresh()
    end
end

function on_game_start(data)
    if registered then
        return
    end

    RegisterScriptCallback("actor_on_info_callback", on_actor_info)
    registered = true
end
```

`on_game_start` регистрирует обработчики и не читает состояние актора. Обработчик инфопорций отбрасывает посторонние события. Повторная выдача уже имеющейся инфопорции не вызывает этот callback: движок отклоняет дубликат. Повторные явные вызовы `refresh()` устанавливают те же абсолютные значения. Регистрация защищена от повторного вызова старта.

Инфопорция, уже имеющаяся в загруженном сохранении, сама по себе не применяет бонус. Загрузка совместимого сохранения восстанавливает записанные коэффициенты и не пересчитывает их по инфопорциям.

Штатный callback сообщает о получении инфопорции, но не о её удалении. После удаления явно обновите коэффициенты:

```lua
local actor = db.actor
actor:disable_info_portion("example_weapon_training")
actor_weapon_modifiers.refresh()
```

Если другой скрипт тоже управляет уроном или отдачей, объедините обработчик с подходом из примера нескольких источников, чтобы скрипты не перезаписывали значения друг друга. Регистрация событий относится к скриптовому Framework; API движка только хранит и применяет коэффициенты.

## Область действия и детали расчёта

- Оружие читает коэффициенты текущего владельца. При смене оружия повторное применение не нужно; выбрасывание или передача оружия не передаёт бонус актора. У NPC, в мультиплеере и у прочих стреляющих объектов используются нейтральные значения.
- Урон и импульс сохраняют штатный учёт улучшений, глушителя и патрона. Эти модификаторы пуль не меняют урон взрывных снарядов и ударов в ближнем бою.
- Меткость масштабирует базовый разброс с учётом состояния оружия, глушителя и патрона, включая путь базового разброса первых выстрелов очереди. В обычном пути стрельбы разброс актора добавляется после этого. Для настроенных первых выстрелов очереди используется только изменённый базовый разброс; расчёт перекрестия при этом продолжает учитывать разброс актора.
- Скорость пули включает текущий множитель глушителя и отдельную начальную скорость первых выстрелов очереди. Гравитация, сопротивление воздуха и максимальная дальность остаются заданными в конфигурации; отдельного коэффициента настильности нет.
- Удобность меняет интерполяцию сведения прицела, а не чувствительность мыши, отдачу или скорость анимаций.
- Отдача действует в обычной и паттернной системах, от бедра и в прицеливании, по обеим осям. Масштабируется толчок нового выстрела с сохранением ограничений углов, шага и скорости. Нейтральный коэффициент сохраняет штатный результат, включая случайное отклонение около предельного угла в обычной системе. Скорость возврата, параметры пружины/затухания и анимации оружия независимы.

## Проверка

После правок C++ или привязок Lua соберите `xrGame`. Приёмка поведения требует отдельной проверки в игре: сохранение/загрузка, повторные события, снятие бонуса, улучшенное оружие, установка/снятие глушителя, владение NPC, оба пути стрельбы и обычная/паттернная отдача.
