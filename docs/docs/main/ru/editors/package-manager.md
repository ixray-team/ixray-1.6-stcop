# Менеджер пакетов SDK

Менеджер открывается пунктом **Packages** рядом с **Plugins** в главном меню редактора. Это общая библиотека пакетов для всех проектов, использующих данную установку SDK.

Нажмите **+ Add package** и выберите **Install from GitHub...**, **Install from folder...** или **Install from archive...**.

Для GitHub вставьте ссылку вида `https://github.com/owner/repository`, при необходимости укажите ветку или тег и нажмите **Add package** (для ассетов — **Download package**). Пустое поле ветки означает текущую ветку репозитория по умолчанию. Нужен Git в `PATH`; для синхронизации каталога также используется curl; поддерживаются публичные репозитории GitHub по HTTPS. Для локальной установки Git не требуется.

Слева находятся **All packages** (весь каталог и пакеты из собственных источников), **My packages** (только установленные), **Official** и **Community** (по источнику каталога). Плагины и ассеты находятся в общих списках. Посередине — поиск и сортировка, справа — **Install package** для доступного пакета либо **Update package / Remove package** для установленного. Локальные данные обновляются автоматически после установки, обновления или удаления пакета. **Sync catalog** синхронизирует удалённый каталог.

Выберите установленный пакет слева, чтобы увидеть версию, источник и каталог установки. **Update package** повторно загружает выбранную ветку/тег или перечитывает исходную папку/архив. **Remove package** удаляет принадлежащий пакету каталог. Если в нём появились изменённые или дополнительные файлы, операция остановится: сохраните свои изменения отдельно и восстановите исходный пакет.

Изменения пакетов записываются в журнал. После прерванной операции SDK восстанавливает прежнюю установку либо завершает очистку перед сканированием плагинов. Пока хранилище занято, другой редактор не может изменять пакеты. Отмена проверяется при перечислении, копировании и сравнении файлов; уже зафиксированное изменение сохраняется.

## Карточка пакета

Правая панель показывает название, ID, версию, тип, автора и лицензию пакета. Ссылки Source, Documentation, Website и Release notes необязательны и появляются только при наличии корректного адреса. Source может вести на GitLab, GitHub или другой HTTPS-сайт. Ссылки открываются в браузере по HTTPS.

Вкладки **Overview**, **Changelog** и **License** показывают описание с документацией, историю изменений и текст лицензии. Overview объединяет краткое описание и README на одной странице; если README нет, остаётся краткое описание. В README и Changelog поддерживаются заголовки, списки и блоки кода; остальная Markdown-разметка остаётся текстом. HTML и внешние изображения не загружаются. Отсутствие документации не мешает установке.

При установке и обновлении тексты сохраняются в `.ixray-packages/installed/<id>/documents.json` отдельно от содержимого плагина или ассетов. Карточка работает без сети и после удаления исходной папки или архива. Старые установки без этого кэша могут использовать документацию каталога для той же версии; обновите пакет, чтобы сохранить его собственные документы. Документация более новой версии из каталога не выдаётся за документацию установленной версии.

До установки **Sync catalog** получает `package.json` и превью README, CHANGELOG и LICENSE из корня репозитория через `raw.githubusercontent.com`, по одному точному коммиту. GitHub REST API и клонирование содержимого пакета для этого не используются. При выборе карточки документы читаются из кэша без сетевого запроса. При неизменившемся коммите синхронизация повторно использует полный кэш данных и документов пакета; неполные превью загружаются повторно. Во время установки документы сохраняются из скачанного пакета.

Для превью до установки разместите `README.md`, `CHANGELOG.md` и `LICENSE.md` в корне репозитория. Дополнительно проверяются `readme.md`, `README.txt`, `README`, `changelog.md`, `CHANGES.md`, `CHANGELOG`, `LICENSE`, `LICENSE.txt`, `license.md` и `COPYING`. Документы необязательны; их отсутствие не блокирует установку. Поддерживается UTF-8 с BOM, превью ограничено 32 КиБ на документ; raw-файлы больше 64 КиБ пропускаются с уведомлением. Для установленных и локальных пакетов дополнительно проверяется папка content, имена сопоставляются без учёта регистра и поддерживаются варианты HISTORY/COPYING. Локальные ссылки и специальные файлы пропускаются.

## Локальные пакеты

Для папки укажите путь к каталогу с `package.json` или к самому манифесту. **Browse...** открывает выбор папки: двойной щелчок открывает каталог, **Up** переходит выше, а **Use this folder** выбирает корень пакета. Путь можно вставить вручную.

ZIP или 7z должен содержать `package.json` в корне или внутри единственной внешней папки. Выберите архив через **Browse...** в системном диалоге или вставьте путь. Тип и содержимое локального пакета задаёт обязательный манифест; примеры ниже подходят для папок, ZIP и 7z.

Менеджер устанавливает отдельную копию. Исходная папка или архив сохраняются. Для обновления измените файлы исходной папки или замените архив по тому же пути и нажмите **Update package**. Если источник перемещён или удалён, обновление остановится, а установленная копия сохранится. Локальный источник должен находиться вне управляемых каталогов SDK `packages`, `plugins/packages`, `.ixray-packages` и не должен содержать эти каталоги.

Распаковка архивов проверяет целостность данных и блокирует ссылки, небезопасные пути, повторяющиеся имена и зашифрованные записи. Ограничения: 100000 записей, 2 ГиБ на файл, 16 ГиБ суммарно после распаковки. ZIP поддерживает Store и Deflate; 7z — Copy, LZMA, LZMA2, PPMd и поддерживаемые фильтры, включая solid-архивы. Декодер встроен в редактор: установка 7-Zip и дополнительные DLL не требуются. Запароленные, многотомные и другие форматы архивов пока не поддерживаются. Старые записи установленных ZIP-пакетов остаются совместимыми.

## Типы пакетов

- Плагины SDK устанавливаются в `plugins/packages/<id>`. Поддерживаются Lua и Python. Список меню Plugins обновляется после завершения операции; открытые окна запуска плагинов необходимо закрыть.
- Библиотеки ассетов: **Download** сохраняет пакет в общей библиотеке `packages/<id>` внутри SDK. **Import** копирует выбранные файлы в рабочие каталоги текущего SDK. Скачивание не импортирует файлы. **Download update**, **Reload download** и **Remove download** изменяют только библиотечную копию; импортированные файлы сохраняются отдельно. Менеджер не запускает скрипты из ассет-пакетов.


Данные менеджера и снимки установленных файлов хранятся в `.ixray-packages` внутри SDK. Этот каталог нужен для обновления и проверки локальных изменений.

## Импорт ассетов

После скачивания ассет-пакета нажмите **Import**. Откроется окно с деревом папок, флажками выбора файлов, конечными путями и причинами пропуска. Размер окна можно менять. Выберите содержимое через **Select all**, **Select none** или отдельные флажки и нажмите **Import**. Предпросмотр сравнивает содержимое и различает отсутствующие, одинаковые, отличающиеся и заблокированные файлы. Отсутствующие выбраны по умолчанию. Одинаковые не требуют копирования. Отличающиеся сохраняются, пока вы не включите **Allow replacing different files (originals are backed up)** и не выберете их для замены. Каталоги и файлы без безопасного назначения недоступны для выбора. Чтобы обновить список после изменений на диске, откройте Import заново.

В каталоге `content`, указанном в манифесте, сохраняется стандартная структура SDK. Например, для `"content": "assets"`:

```text
assets/
  rawdata/
    objects/example/house.object
    objects/example/house.thm
    levels/example.level
    levels/example/scene_object.part
  gamedata/
    textures/example/brick.dds
  import/
    source_texture.tga
```

Конечные каталоги берутся из алиасов действующего `fs.ltx`: `rawdata/objects` — `$objects$`, `rawdata/levels` — `$maps$`, `rawdata/groups` — `$groups$`, исходные текстуры и звуки — `$textures$` и `$sounds$`. Стандартные разделы `gamedata` используют соответствующие `$game_...$`, а `import` — `$import$`. Остальные подкаталоги `rawdata` и `gamedata` размещаются относительно `$server_data_root$` и `$game_data$`. Применяется наиболее точное соответствие; отсутствующий алиас отмечается в окне импорта. Вложенные пути сохраняются. Импорт в служебные каталоги менеджера пакетов запрещён.

Автор пакета должен включить необходимые зависимости: для уровня нужны его папка `.part`, модели, текстуры и другие используемые ресурсы. Проверка зависимостей показывает поддерживаемые ссылки, но не скачивает зависимости и не переписывает ссылки внутри ресурсов. Импорт копирует подготовленные файлы; размещение исходников в `import` не запускает конвертацию или компиляцию автоматически.

Проверка зависимостей необязательна. Откройте **Details** и нажмите **Check dependencies**, когда она нужна; после изменения выбора файлов запустите её снова для обновления результата. Список различает **Missing** — отсутствует, **Not selected** — есть в пакете, но не выбран, **In SDK** — уже доступен в SDK, **Selected** — выбран для импорта. Показано, какая сцена или модель требует ресурс. Сохранённые файлы SDK проверяются по текущему содержимому, а выбранные замены — по версии из пакета. Проверка работает в фоне и поддерживает отмену. **Import** копирует выбранные файлы без проверки зависимостей; её предупреждения не блокируют копирование.

Кнопка **Select dependencies** отмечает необходимые файлы, доступные в этом пакете. Она заново проверяет выбранные уровни и повторяет анализ после выбора метаданных, пока не перестанут появляться новые файлы для выбора. Существующие файлы SDK не выбираются для замены, ручной выбор сохраняется. Отсутствующие ресурсы и нечитаемые файлы остаются в отчёте. Действие работает в фоне; при отмене или ошибке набор выбранных файлов не меняется. Копирование начинается только после **Import**.

Поддерживаются ссылки на редактируемые объекты в LTX и поддерживаемых бинарных файлах сцены, вложенные группы, detail-модели, переопределения поверхностей, текстуры glow/света и форматы поверхностей `.object` `0x0905`–`0x0908`, включая общие материалы из `SharedMaterials.ltx`. Terrain-шаблоны определяются по классу `B_BmmD` в действующем `shaders.xr`; их неявная текстура `<texture>_mask.dds` тоже проверяется. Для текстур учитывается приоритет рендера: `.ogm`, `.avi`, `.seq`, затем обычный `.dds`. Кадры DDS проверяются в действующем `$level$` и `$game_textures$`; bump DDS из папки уровня учитывается только при наличии глобального DDS, как в загрузчике рендера. Анализ не открывает уровень, не загружает ресурсы рендера и не пересохраняет модели. Нечитаемые, повреждённые и сжатые секции зависимостей отмечаются как неполная проверка. Это не полная валидация уровня: пока не разрешаются остальные текстуры, добавляемые шейдерами, базовые карты рисования травы и другие игровые ресурсы.

Ссылки bump/detail берутся сначала из `textures.ltx`, затем из действующих `.thm` в `$game_textures$` и `$level$`. Спецификация THM заменяет предыдущие настройки bump; detail-ассоциация заменяется только при включённой настройке detail в THM. Для включённого bump проверяются указанное изображение и его парный файл с `#`. Bump detail-текстуры проверяется только при включённом bump-detail. В отчёте показано, какая текстура или последовательность требует изображение. Исходные thumbnail из `rawdata/textures` не считаются настройками рендера. Невыбранные необязательные метаданные отображаются как **Not selected**, а их настройки не применяются к предпросмотру.

Для `.seq` читается необязательный заголовок `cycled`, проверяется частота 1–1000 FPS и наличие каждого кадра как обычного DDS. Одноимённый базовый DDS для последовательности не требуется. Ограничения: 1 МиБ на `.seq`, 10000 кадров, 254 байта на строку, как в буфере рендера. UTF-8 BOM и пробелы вокруг заголовка `cycled` отмечаются как неподдерживаемые: загрузчик игры их не принимает. Повреждённые данные, небезопасные пути кадров и неподдерживаемые метаданные отмечаются как неполная проверка. Для видеотекстур проверяется наличие файла; декодирование видео в анализ не входит.

Импорт выполняется в фоне с прогрессом и отменой. Перед записью источники и назначения сверяются с предпросмотром, включая изменения содержимого без изменения размера. Перед выбранной заменой создаётся и проверяется резервная копия; эксклюзивное создание защищает файлы, появившиеся после предпросмотра. При отмене или обнаруженной ошибке новые копии удаляются, а заменённые оригиналы восстанавливаются. Если восстановление не удалось, отчёт указывает проблемный файл, а резервная копия сохраняется. После успешного импорта обновляются файловая система и открытые Content Browser.

После успешного импорта менеджер показывает короткое сообщение с числом импортированных файлов. Полный отчёт доступен по кнопке **Last import report**, пока окно менеджера остаётся открытым. При ошибке отчёт открывается автоматически. Счётчики учитывают все результаты, но совпадающие файлы не выводятся в таблице. Отчёты и оригиналы сохраняются в `.ixray-packages/import-history/import-<id>/`: `report.json` содержит конечные пути и пути резервных копий. Для каждой проверенной копии также сохраняется отдельная запись `restore-<index>.json`. При повторном открытии Import список сканируется заново: неизменённые файлы отмечаются как одинаковые, а отредактированные можно явно выбрать для замены.

Принудительное завершение редактора может оставить неполный импорт. Автоматического восстановления при запуске нет: при необходимости проверьте сохранённый отчёт и записи restore, затем восстановите оригиналы из резервных копий. Скачанный пакет остаётся без изменений.

## Формат репозитория

Поместите `package.json` в корень пакета. Для локальных папок и архивов он обязателен; для GitHub рекомендуется:

```json
{
  "id": "example.shared-assets",
  "name": "Example Asset Library",
  "version": "1.0.0",
  "description": "Reusable assets for SDK projects",
  "author": "Example Author",
  "type": "assets"
}
```

Основные типы: `sdk-plugin` и `assets`. `name`, `version`, `description` и `author` — необязательные строки. `id` должен быть постоянным, в нижнем регистре, из латинских букв, цифр, точек, дефисов и подчёркиваний. При обновлении тип, ID и репозиторий менять нельзя.

`content` — необязательное поле. Если файлы лежат рядом с `package.json`, пропустите его: будет использован корень пакета. Указывайте поле только для вложенной папки, например `"content": "content"` или `"content": "editors"`. Название папки произвольное; SDK использует заданный относительный путь и сообщает об ошибке, если папки нет. Явно заданный каталог не заменяется корнем автоматически.

| Структура рядом с `package.json` | `content` |
| --- | --- |
| `rawdata/`, `gamedata/`, `import/` | Пропустить поле |
| `content/rawdata/`, `content/gamedata/` | `"content": "content"` |
| `editors/rawdata/`, `editors/gamedata/` | `"content": "editors"` |
| Папки со скриптами плагинов `core/`, `src/` | Пропустить поле, чтобы включить обе |

Структура внутри выбранного каталога сохраняется. Чтобы Import определил назначения ассетов через `fs.ltx`, папки `rawdata/`, `gamedata/` и `import/` должны лежать непосредственно в этом каталоге; добавляйте только нужные пакету папки. Скрипты плагина ищутся рекурсивно, поэтому будут найдены и в `core/`, и в `src/`. Каждый `.lua` или `.py` становится отдельной командой Plugins.

Пакет `sdk-plugin` объединяет один или несколько скриптов для установки, обновления и удаления. Он использует существующий загрузчик плагинов; отдельный входной скрипт через `package.json` не задаётся. Например, пакет с `core/tool-a.lua` и `src/tool-b.py` устанавливает обе папки и добавляет две команды. Названия команд берутся из имён файлов, описания и параметры — из существующих комментариев `desc` и `input`. Каждый Lua/Python-файл в устанавливаемом содержимом должен быть рассчитан на использование как команда плагина: служебные модули текущий загрузчик тоже обнаруживает.

Необязательные поля карточки: `license` (название/идентификатор от автора, до 256 байт UTF-8), `sourceUrl`, `websiteUrl`, `documentationUrl`, `changelogUrl` (до 2048 байт каждое). Ссылки должны использовать HTTPS и DNS-имя без учётных данных и нестандартного порта. В старых манифестах все эти поля можно пропустить. `sourceUrl` задаёт ссылку на исходники независимо от источника установки. Если поле пропущено, используется известный URL GitHub-репозитория, если он есть. Без ссылки на документацию скрывается Documentation, без ссылки на исходники — Source. Вкладка License показывает приложенный файл лицензии; тип пакета не определяет условия его использования.

Без манифеста ID получается из `owner.repository`, а тип задаётся в окне добавления. Для плагинов используется папка `plugins`, если она есть, иначе корень репозитория; в содержимом должен присутствовать хотя бы один `.lua` или `.py`. Для ассетов используется корень.


## Каталог Official / Community

Публикуемый `sdk-packages.json` содержит только массивы ссылок `official` и `community`. Поля `schemaVersion`, описаний и типов пакетов в нём нет:

```json
{
  "official": ["https://github.com/example/sdk-tools"],
  "community": []
}
```

Адрес выше — шаблон: замените его настоящим публичным репозиторием с `package.json` в корне. Для конкретной ветки или тега вместо строки можно указать `{"url":"https://github.com/example/sdk-tools","ref":"main"}`. Простая ссылка использует ветку по умолчанию. Старый формат с полными записями не поддерживается.

ID, название, тип, версия, описание, автор, категория и необязательные ссылки карточки читаются из `package.json` самого пакета. Необязательные строки `readme`, `changelog`, `licenseText` служат запасным превью, если файлов документов в репозитории нет (до 32 КиБ каждая, в пределах лимита манифеста 64 КиБ). Raw-документы сохраняются отдельно и не входят в размер манифеста. При обновлениях сохраняйте ID и тип пакета.

**Sync catalog** использует источник каталога, заданный в SDK и читает `sdk-packages.json` из ветки репозитория по умолчанию. Поставлять файлы каталога вместе с SDK не требуется. В фоне определяются ревизии пакетов и загружаются их манифесты по HTTPS. Нужны Git и curl в PATH. Установка из каталога использует точный коммит карточки; Update следует сохранённой ветке/тегу. Фиксированный тег остаётся фиксированным.

Отдельная репа содержит список ссылок и инструкцию. Примеры пакетов находятся в собственных репозиториях и не поставляются с движком. До первой синхронизации каталог свежего SDK пуст.

Чтобы изменить источник, создайте `package-manager.json` в `$app_data_root$` (обычно `_appdata_ixray_`):

Все поля необязательны; пустой `ref` означает ветку репозитория по умолчанию. Настройки перечитываются при каждой синхронизации; файл автоматически не создаётся. Его удаление возвращает встроенный источник. Некорректные явные настройки вызывают ошибку. Старый `package-catalog/registry.json` больше не используется.

Внутренний снимок `.ixray-packages/catalog.json` хранит индекс, загруженные манифесты и превью документов для работы без сети. Открытие окна и перечитывание локальных данных после операций с пакетами не обращаются к сети. Если один репозиторий недоступен, сохранённая карточка остаётся с пометкой об устаревших данных; без кэша пакет виден как недоступный, установка заблокирована. Некорректный индекс и отмена сохраняют предыдущий снимок. Старые кэши полного каталога игнорируются. Установленные пакеты не зависят от наличия ссылки в каталоге.

Official/Community назначает владелец каталога; это не цифровая подпись. Ограничения: до 128 ссылок на раздел, 64 КиБ на индекс или загружаемый манифест, 32 МиБ на внутренний снимок. Репозиторий с выбранной ревизией можно указать один раз. Повторяющиеся ID манифестов отмечаются как недоступные конфликты. Другой установленный источник с тем же ID остаётся в My packages и не перезаписывается каталогом.

## Ограничения

Поддерживаются публичные репозитории GitHub. Авторизация для приватных репозиториев, автоматическая установка зависимостей пакетов, загрузка содержимого Git LFS и подмодулей не реализованы.

При установке и обновлении пакета команды его плагинов и установочные скрипты не выполняются. Установленные плагины доступны в меню **Plugins**. Символические ссылки отклоняются.

Сетевые операции поддерживают отмену. Для команд Git clone/fetch установлен тайм-аут 180 секунд, для определения ревизии — 20 секунд. HTTP-запросы метаданных и документов ограничены 15 секундами, включая до 5 секунд на подключение. Эти ограничения действуют отдельно для каждой команды или запроса; вся установка или синхронизация каталога может занять больше времени.
