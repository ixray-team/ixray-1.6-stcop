# Менеджер пакетов SDK

Менеджер открывается пунктом **Packages** рядом с **Plugins** в главном меню редактора. Это общая библиотека пакетов для всех проектов, использующих данную установку SDK.

Нажмите **+ Add package** и выберите **Install from GitHub...**, **Install from folder...** или **Install from ZIP...**.

Для GitHub вставьте ссылку вида `https://github.com/owner/repository`, при необходимости укажите ветку или тег и нажмите **Install package**. Пустое поле ветки означает текущую ветку репозитория по умолчанию. Нужен Git в `PATH`; для синхронизации каталога также используется curl; поддерживаются публичные репозитории GitHub по HTTPS. Для локальной установки Git не требуется.

Слева находятся **All packages** (весь каталог и пакеты из собственных источников), **My packages** (только установленные), **Official** и **Community** (по источнику каталога). Плагины и ассеты находятся в общих списках. Посередине — поиск и сортировка, справа — **Install package** для доступного пакета либо **Update package / Remove package** для установленного. Локальные данные обновляются автоматически после установки, обновления или удаления пакета. **Sync catalog** синхронизирует удалённый каталог.

Выберите установленный пакет слева, чтобы увидеть версию, источник и каталог установки. **Update package** повторно загружает выбранную ветку/тег или перечитывает исходную папку/ZIP. **Remove package** удаляет принадлежащий пакету каталог. Если в нём появились изменённые или дополнительные файлы, операция остановится: сохраните свои изменения отдельно и восстановите исходный пакет.

Изменения пакетов записываются в журнал. После прерванной операции SDK восстанавливает прежнюю установку либо завершает очистку перед сканированием плагинов. Пока хранилище занято, другой редактор не может изменять пакеты. Отмена проверяется при перечислении, копировании и сравнении файлов; уже зафиксированное изменение сохраняется.

## Карточка пакета

Правая панель показывает название, ID, версию, тип, автора и лицензию пакета. Ссылки Source, Documentation, Website и Release notes необязательны и появляются только при наличии корректного адреса. Source может вести на GitLab, GitHub или другой HTTPS-сайт. Ссылки открываются в браузере по HTTPS.

Вкладки **Overview**, **Changelog** и **License** показывают описание с документацией, историю изменений и текст лицензии. Overview объединяет краткое описание и README на одной странице; если README нет, остаётся краткое описание. В README и Changelog поддерживаются заголовки, списки и блоки кода; остальная Markdown-разметка остаётся текстом. HTML и внешние изображения не загружаются. Отсутствие документации не мешает установке.

При установке и обновлении тексты сохраняются в `.ixray-packages/installed/<id>/documents.json` отдельно от содержимого плагина или ассетов. Карточка работает без сети и после удаления исходной папки или ZIP. Старые установки без этого кэша могут использовать документацию каталога для той же версии; обновите пакет, чтобы сохранить его собственные документы. Документация более новой версии из каталога не выдаётся за документацию установленной версии.

До установки **Sync catalog** получает `package.json` и превью README, CHANGELOG и LICENSE из корня репозитория через `raw.githubusercontent.com`, по одному точному коммиту. GitHub REST API и клонирование содержимого пакета для этого не используются. При выборе карточки документы читаются из кэша без сетевого запроса. При неизменившемся коммите синхронизация повторно использует полный кэш данных и документов пакета; неполные превью загружаются повторно. Во время установки документы сохраняются из скачанного пакета.

Для превью до установки разместите `README.md`, `CHANGELOG.md` и `LICENSE.md` в корне репозитория. Дополнительно проверяются `readme.md`, `README.txt`, `README`, `changelog.md`, `CHANGES.md`, `CHANGELOG`, `LICENSE`, `LICENSE.txt`, `license.md` и `COPYING`. Документы необязательны; их отсутствие не блокирует установку. Поддерживается UTF-8 с BOM, превью ограничено 32 КиБ на документ; raw-файлы больше 64 КиБ пропускаются с уведомлением. Для установленных и локальных пакетов дополнительно проверяется папка content, имена сопоставляются без учёта регистра и поддерживаются варианты HISTORY/COPYING. Локальные ссылки и специальные файлы пропускаются.

## Локальные пакеты

Для папки укажите путь к каталогу с `package.json` или к самому манифесту. **Browse...** открывает выбор папки: двойной щелчок открывает каталог, **Up** переходит выше, а **Use this folder** выбирает корень пакета. Путь можно вставить вручную.

ZIP должен содержать `package.json` в корне или внутри единственной внешней папки. Выберите архив через **Browse... → Use ZIP archive** или вставьте путь. Тип и содержимое локального пакета задаёт обязательный манифест; примеры ниже подходят для папок и ZIP.

Менеджер устанавливает отдельную копию. Исходная папка или ZIP сохраняются. Для обновления измените файлы исходной папки или замените ZIP по тому же пути и нажмите **Update package**. Если источник перемещён или удалён, обновление остановится, а установленная копия сохранится. Локальный источник должен находиться вне управляемых каталогов SDK `packages`, `plugins/packages`, `.ixray-packages` и не должен содержать эти каталоги.

Распаковка ZIP проверяет CRC и блокирует ссылки, небезопасные пути, повторяющиеся имена и зашифрованные записи. Ограничения: 100000 записей, 2 ГиБ на файл, 16 ГиБ суммарно после распаковки. Поддерживаются обычные ZIP с сохранёнными или Deflate-сжатыми файлами; tarball не поддерживается.

## Типы пакетов

- Плагины SDK устанавливаются в `plugins/packages/<id>`. Поддерживаются Lua и Python. Список меню Plugins обновляется после завершения операции; открытые окна запуска плагинов необходимо закрыть.
- Пакеты ассетов устанавливаются в `packages/<id>` внутри SDK: модели, текстуры, звуки и другие файлы. Пакет должен содержать хотя бы один файл. Содержимое хранится как общая библиотека; автоматическое подключение к Content Browser и импорт в проект пока не реализованы. Скрипты внутри пакета ассетов не запускаются.


Данные менеджера и снимки установленных файлов хранятся в `.ixray-packages` внутри SDK. Этот каталог нужен для обновления и проверки локальных изменений.

## Формат репозитория

Поместите `package.json` в корень пакета. Для локальных папок и ZIP он обязателен; для GitHub рекомендуется:

```json
{
  "id": "example.shared-assets",
  "name": "Example Asset Library",
  "version": "1.0.0",
  "description": "Reusable assets for SDK projects",
  "author": "Example Author",
  "type": "assets",
  "content": "assets"
}
```

Основные типы: `sdk-plugin` и `assets`. `name`, `version`, `description` и `author` — необязательные строки. `content` — относительный каталог внутри репозитория; по умолчанию используется корень. `id` должен быть постоянным, в нижнем регистре, из латинских букв, цифр, точек, дефисов и подчёркиваний. При обновлении тип, ID и репозиторий менять нельзя.

Необязательные поля карточки: `license` (название/идентификатор от автора, до 256 байт UTF-8), `sourceUrl`, `websiteUrl`, `documentationUrl`, `changelogUrl` (до 2048 байт каждое). Ссылки должны использовать HTTPS и DNS-имя без учётных данных и нестандартного порта. В старых манифестах все эти поля можно пропустить. `sourceUrl` задаёт ссылку на исходники независимо от источника установки. Если поле пропущено, используется известный URL GitHub-репозитория, если он есть. Без ссылки на документацию скрывается Documentation, без ссылки на исходники — Source. Вкладка License показывает приложенный файл лицензии; тип пакета не определяет условия его использования.

Без манифеста ID получается из `owner.repository`, а тип задаётся в окне добавления. Для плагинов используется папка `plugins`, если она есть, иначе корень репозитория; в содержимом должен присутствовать хотя бы один `.lua` или `.py`. Для ассетов используется корень.


## Каталог Official / Community

Публикуемый `sdk-packages.json` содержит только массивы ссылок `official` и `community`. Поля `schemaVersion`, описаний и типов пакетов в нём нет:

```json
{
  "official": ["https://github.com/example/sdk-tools"],
  "community": []
}
```

Адрес выше — шаблон: замените его настоящим публичным репозиторием с `package.json` в корне. Для конкретной ветки или тега вместо строки можно указать `{"url":"https://github.com/example/sdk-tools","ref":"main"}`. Простая ссылка использует ветку по умолчанию. Старый формат с полными записями не поддерживается.

ID, название, тип, версия, описание, автор, категория и необязательные ссылки карточки читаются из `package.json` самого пакета. Необязательные строки `readme`, `changelog`, `licenseText` служат запасным превью, если файлов документов в репозитории нет (до 32 КиБ каждая, в пределах лимита манифеста 64 КиБ). Raw-документы сохраняются отдельно и не входят в размер манифеста. При обновлениях сохраняйте ID и тип пакета.

**Sync catalog** использует источник каталога, заданный в SDK и читает `sdk-packages.json` из ветки репозитория по умолчанию. Поставлять файлы каталога вместе с SDK не требуется. В фоне определяются ревизии пакетов и загружаются их манифесты по HTTPS. Нужны Git и curl в PATH. Установка из каталога использует точный коммит карточки; Update следует сохранённой ветке/тегу. Фиксированный тег остаётся фиксированным.

Отдельная репа содержит список ссылок и инструкцию. Примеры пакетов находятся в собственных репозиториях и не поставляются с движком. До первой синхронизации каталог свежего SDK пуст.

Чтобы изменить источник, создайте `package-manager.json` в `$app_data_root$` (обычно `_appdata_ixray_`):

Все поля необязательны; пустой `ref` означает ветку репозитория по умолчанию. Настройки перечитываются при каждой синхронизации; файл автоматически не создаётся. Его удаление возвращает встроенный источник. Некорректные явные настройки вызывают ошибку. Старый `package-catalog/registry.json` больше не используется.

Внутренний снимок `.ixray-packages/catalog.json` хранит индекс, загруженные манифесты и превью документов для работы без сети. Открытие окна и перечитывание локальных данных после операций с пакетами не обращаются к сети. Если один репозиторий недоступен, сохранённая карточка остаётся с пометкой об устаревших данных; без кэша пакет виден как недоступный, установка заблокирована. Некорректный индекс и отмена сохраняют предыдущий снимок. Старые кэши полного каталога игнорируются. Установленные пакеты не зависят от наличия ссылки в каталоге.

Official/Community назначает владелец каталога; это не цифровая подпись. Ограничения: до 128 ссылок на раздел, 64 КиБ на индекс или загружаемый манифест, 32 МиБ на внутренний снимок. Репозиторий с выбранной ревизией можно указать один раз. Повторяющиеся ID манифестов отмечаются как недоступные конфликты. Другой установленный источник с тем же ID остаётся в My packages и не перезаписывается каталогом.

## Ограничения

Поддерживаются публичные репозитории GitHub. Авторизация для приватных репозиториев, автоматическая установка зависимостей пакетов, загрузка содержимого Git LFS и подмодулей не реализованы.

При установке и обновлении пакета команды его плагинов и установочные скрипты не выполняются. Установленные плагины доступны в меню **Plugins**. Символические ссылки отклоняются.

Сетевые операции поддерживают отмену. Для команд Git clone/fetch установлен тайм-аут 180 секунд, для определения ревизии — 20 секунд. HTTP-запросы метаданных и документов ограничены 15 секундами, включая до 5 секунд на подключение. Эти ограничения действуют отдельно для каждой команды или запроса; вся установка или синхронизация каталога может занять больше времени.
