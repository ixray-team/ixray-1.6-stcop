# Столкновения машины с персонажами

Документ описывает текущее поведение тарана и толкания персонажей после
коммитов `08e201a72d` и `5addab76b1`, а также параметры конфигурации из
`configs/misc/vehicles.ltx`. Это справка по поведению, а не спецификация
исходной системы Cars-Ext.

## 1. Два независимых механизма

Сейчас в машине есть два разных механизма, которые не следует путать.

### 1.1. Урон от столкновения

Урон считает обычный legacy-путь `CPHMovementControl::UpdateCollisionDamage()`:

- `CPHSimpleCharacter::UpdateDynamicDamage()` вычисляет `fContactSpeed` из
  энергии контакта;
- если `fContactSpeed` выше `ph_crash_speed_min` жертвы, начисляется
  `gcontact_HealthLost = (fContactSpeed - min) / (max - min)`;
- урон применяется через `CMovementManager::apply_collision_hit()` для
  мутантов/НПС или через `Actor.cpp` для актёра;
- `ram_damage_min_speed` из секции машины является дополнительным порогом
  **скорости автомобиля**. Если он задан и машина едет медленнее, `fContactSpeed`
  обнуляется до расчёта урона.

`ram_damage_min_speed` задаётся в **км/ч**. Если ключ отсутствует, значение
равно `0`, то есть дополнительного порога нет.

### 1.2. Физическое толкание мутанта

Коммит `08e201a72d` добавил отдельный слой для живых мутантов:

- `CCar::CarRamCallback()` регистрируется на основном shell машины;
- callback запоминает контакт в `CPHMovementControl::SetCarContact()` на
  `ram_contact_memory` миллисекунд;
- `CPHMovementControl::ApplyCarContact()` ограничивает нормальную компоненту
  скорости мутанта и добавляет импульс от машины;
- `CMovementManager::move_along_path()` применяет этот контакт каждый кадр,
  пока он свежий;
- `CPHSimpleCharacter::m_external_push` отключает обычное управление
  ускорением/торможением на время контакта.

Этот слой **не наносит урон**. Он только меняет скорость мутанта. NPC, актёр и
ragdoll’ы в нём не участвуют: `CarRamCallback()` явно требует
`Other->cast_base_monster() != nullptr` и живого `CEntityAlive`.

## 2. Параметры

Все ключи читаются из секции машины (`[m_car_base]` или секция конкретной
модели/класса) в `CCar::LoadHandlingAndCameraDefinitions()`.

| Ключ | Единицы | По умолчанию | Диапазон | Назначение |
| --- | --- | --- | --- | --- |
| `ram_damage_min_speed` | км/ч | `0` | `>= 0` | Минимальная скорость машины для collision damage; `0` — без порога |
| `ram_push_scale` | множитель | `1.5` | `0..10` | Масштаб нормального импульса толкания |
| `ram_max_push_speed` | м/с | `25` | `0..100` | Верхний предел добавляемой нормальной скорости |
| `ram_contact_memory` | мс | `150` | `0..2000` | Сколько времени контакт считается свежим |
| `ram_min_speed` | м/с | `1` | `0..50` | Минимальная нормальная скорость машины, при которой она толкает мутанта |
| `ram_separation_bias` | м/с | `3` | `0..15` | Добавка к целевой нормальной скорости, чтобы вытолкнуть мутанта из машины |
| `ram_mutant_push_speed` | м/с | `0.5` | `0..5` | Максимальная скорость, с которой мутант может «толкать» машину |
| `gigant_kick_impulse` | кг·м/с | `-1` | `>= 0`, иначе legacy | Импульс удара псевдогиганта по машине; `-1` — legacy `20 * масса`, `0` — отключить |

Старые параметры персонажей (`ph_crash_speed_min`, `ph_crash_speed_max`,
`ph_collision_damage_factor`) продолжают действовать на этапе расчёта
`fContactSpeed`. Они задаются в `configs/creatures/*.ltx`, а не в
`vehicles.ltx`.

## 3. Что происходит с разными целями

| Цель | Урон от машины | Физическое толкание из `CarRamCallback` |
| --- | --- | --- |
| Мутант (`CBaseMonster`) | Да, через `UpdateCollisionDamage` + пороги персонажа | Да |
| НПС-сталкер | Да, через `UpdateCollisionDamage` + пороги персонажа | Нет |
| Актёр | Да, через `Actor.cpp` + пороги актёра | Нет |
| Ragdoll/труп | Физика, без `CarRamCallback` | Нет |

## 4. Найденные проблемы и риски

### 4.1. Два порога не связаны

`ram_damage_min_speed` и `ram_min_speed` имеют разные единицы и разные
механизмы. При `ram_damage_min_speed = 150` машина на низкой скорости не
наносит прямой collision damage, но всё ещё может толкать мутанта через
`CarRamCallback` (`ram_min_speed` по умолчанию `1 м/с`). Если мутанта
подбрасывает или он падает, смерть может наступить от падения, а не от
прямого урона машины. Это главная причина, по которой параметр может
выглядеть «не работающим» при наблюдении за смертью мутанта.

### 4.2. `m_external_push` может остаться включённым

`m_external_push` сбрасывается в `CPHMovementControl::UpdateCarContact()`,
который вызывается из `CMovementManager::move_along_path()`. Если движение
монстра перестаёт обновляться (смерть, смена состояния, отключение
movement manager) до истечения контакта, флаг может остаться включённым:
`PhDataUpdate()` перестаёт вызывать `Disabling()`, а `ApplyAcceleration()`
выходит раньше. Для актёра добавлен отдельный сброс в `PhTune()`, для
мутантов такого сброса нет. Это риск «залипания» движения.

### 4.3. Box3D не реализует external push

`IPHCharacter::SetExternalPush()` имеет пустую реализацию по умолчанию, а
`CB3Character` (`src/xrPhysics/Box3D/B3Character.cpp`) её не переопределяет.
На ODE-пути (`CPHSimpleCharacter`) режим работает, на Box3D — нет. Поведение
толкания на разных физических бэкендах будет различаться.

### 4.4. Толкание только для мутантов

`CarRamCallback()` явно отбрасывает всё, кроме `CBaseMonster`. НПС и актёр
не получают новый физический слой; для них остаётся только legacy collision
damage. Если требование «толкать и НПС» остаётся, реализация неполная.

### 4.5. Скорость берётся у корневого элемента

`CarRamCallback()` вызывает `get_ElementByStoreOrder(0)->GetPointVel()`.
Для контакта с колесом, дверью или другим элементом скорость точки может
отличаться от скорости корневого элемента. Для большинства кузовных
контактов это приемлемо, но для колёс и вращающихся деталей возможна
неточность.

### 4.6. Обрабатывается только основной shell

`CarRamCallback()` добавляется в `m_pPhysicsShell`, но не в
`characters_scraper_shell`. Контакты, приходящие только через scraper, не
создают car contact для толкания.

### 4.7. ABI-замечание в `IPHCharacter`

`SetExternalPush()` добавлен в интерфейс перед виртуальным деструктором.
Комментарий утверждает, что метод оставлен в конце, чтобы не сдвигать слоты
старых модулей, но деструктор находится после него, поэтому слот деструктора
всё равно сдвигается. Все модули, использующие `IPHCharacter`, должны быть
пересобраны; для внешних предкомпилированных модулей это ABI-риск.

### 4.8. Прочие замечания

- `ram_contact_memory` хранится как `float`, но передаётся в `u32`: дробные
  миллисекунды усекаются.
- `CarRamCallback()` не проверяет `Car->getDestroy()`; проверяется только
  наличие и активность shell.
- `ApplyGigantKick()` намеренно игнорирует `rs_car_god`; это задокументировано
  в коде, но может удивить при тестировании.
- `pseudo_gigant.cpp` для не-машин по-прежнему обращается к
  `obj->m_pPhysicsShell` без проверки на `nullptr`; это унаследованное
  поведение, но новый код его не устраняет.
- `bloodsucker_vampire_execute_inline.h` и `bloodsucker_vampire_inline.h`
  дублируют проверку `actor->IsInCar()`; функционально безвредно.
- Состояние car contact не синхронизируется по сети; в MP возможны
  расхождения.
