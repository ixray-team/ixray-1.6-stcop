# In-game AI Grid Editor

Opening: **Game → Editors → AI Grid Editor**, right after Detail Layers Editor. The editor is available in configurations with `DEBUG_DRAW`, like the other in-game ImGui tools. Alt toggles ImGui mouse capture.

## Controls

- **Enable 3D brush** turns on a solid brush. The radius is 0.5–10 metres, with no noise or probabilistic fill. Holding LMB generates nodes on the static surface under the cursor; RMB deletes them. The brush is green while painting and red while deleting. After a deletion, LMB can restore a node with its previous ID.
- The brush updates existing nodes inside the stroke and recomputes their outgoing directions. The IDs of these nodes are kept. New nodes are appended to the end of the array. Nodes on another floor in the same column are not merged.
- Surface picking skips materials with `flPassable`/`flActorObstacle`, like the Detail Layers Editor brush. The passage check between cells takes `flActorObstacle` into account so it does not cross invisible walls. Dynamic objects do not take part. Static vegetation must have the corresponding material flags.
- **Only paint connected to existing grid** turns on connectivity protection (on by default). Turn it off to paint separate areas inside buildings; the surface, angle, material and wall checks still apply when links are created. With protection on, new cells are first collected into a temporary set, and only cells reachable from the existing active grid through neighbouring cells without crossing walls are painted; the brush does not create a separate island on the backdrop behind a fence. This is protection by connectivity and static collision, not a separate level-boundary polygon: if the fence has a passable gap, or a grid already exists behind it, that area is not treated as forbidden.
- **Filter surface angle** enables a minimum and maximum angle of the normal relative to `(0, 1, 0)` in degrees, from 0 to 180. 0° is a floor facing up, 90° is a wall. When off, the generator's standard slope limit remains. The centre and four edges of the cell are checked; the support and passability checks apply independently of the angle range.
- **Only captured material** allows generation only on the captured game material. The **Capture material** button next to it does a static raycast through the centre of the view and immediately shows the material name. This is the `gamemtl` physical material, not the texture name. On a miss, the previous material is kept; with the filter on and no material captured, painting is blocked. The centre and edges of the cell are checked. The filters apply to LMB painting; RMB deletion is not restricted by them.
- **Edit individual node** enables selecting a node by clicking. The selected node is highlighted in orange. A cross of buttons toggles the outgoing links: left −X, top +Z, right +X, bottom −Z. Green means the link is on, red means it is off. The neighbouring node's back link does not change during manual editing. A direction cannot be enabled without a neighbouring node.
- For the selected node, **Edit node height Y** opens the **Position Y (m)** field: dragging changes the height with a sensitivity step of 0.05 m; Ctrl+click allows entering an exact value. The node moves immediately in the editor's rendering; X/Z, the normal and link directions are kept. The height is packed into the original format on apply/save, extending the vertical bounds if necessary. **Delete selected node** deletes exactly the selected ID, clearing its outgoing and all incoming links without deleting other nodes in the same column. Game graph anchor nodes are protected from deletion. **Apply realtime** and **Overwrite save** are used to change the live AI and to write to disk.
- **Edit node tilt X/Z** opens two independent tilt angles of the selected node relative to the world X and Z axes, from −89° to +89°. 0/0 means a horizontal plane; **Reset node tilt** returns it to that position. The fields support dragging and exact input with Ctrl+click. The change updates the normal and the corners of the displayed cell around its centre, keeping the position and link directions. The normal is written into the standard packed `plane` field of the original grid version, so a small quantisation error is possible after apply/save. The angles describe independent slopes of the plane, not a sequence of Euler rotations; vertical planes are excluded.
- **Apply realtime** applies the working copy on the next `seqFrame`, before GameThread starts. The real level graph and cross table change. The coordinate index, route/restrictor caches, the Level Inspector cache and static cover points are updated. Smart-cover objects stay alive.
- **Delete invalid nodes** removes from the working copy the nodes without valid outgoing links, and the components that contain no complete node with four valid directions. One-way links are also taken into account when finding components; links to deleted nodes and to the node itself do not count as valid. Classification is done once before deletion, without cascading deletion of ordinary edges. Game graph anchor nodes are protected; incoming links to deleted nodes are cleared, the other IDs are kept. The result and the number of protected nodes are shown in the status. The criterion is topological, not by the inspector's RGB colour: a narrow separate corridor without a complete node will also be cleaned up. Use the usual buttons to apply/save, and **Revert to saved** to undo.
- **Revert to saved** restores the working copy from disk: first `level.ai.editor`; if it is missing, the matching pair of native export and remap; then the original `level.ai`. The restored copy is automatically applied to the live AI on the next `seqFrame`; the save on disk is not overwritten.
- **Overwrite save** overwrites, with one button, the patch for the next restart, the native export and the remap. The SDK file is created when the compiler supports the current format; an old incompatible SDK source is deleted. Only `level.ai.editor` is loaded automatically the next time the level is entered. Applying and saving are separate actions.
- **Delete nodes without path to selected**: first turn on **Edit individual node** and select a node on the main street grid. The button deletes the nodes from which the selected one cannot be reached along link directions, including complete isolated islands. This is directed reachability, not mere adjacency: a one-way path from the street to an island does not guarantee a way back. The reference node and game graph anchors are kept; incoming links to deleted nodes are cleared. Working IDs do not change; apply, save and revert are done with the usual buttons. The map size in kilometres is not used: the reverse graph is stored in compact arrays, and the analysis is O(N + E), where E does not exceed 4N. It runs only from the button, on the main thread; on a multi-million-node grid a UI pause and a temporary rise in memory are possible.

Deleted nodes disappear from rendering, coordinate lookup and routes. In the runtime patch their IDs remain as service slots so the IDs of the remaining nodes are not shifted. All outgoing links of a deleted node and incoming links to it are cut on apply/save. Game graph anchor nodes are kept: removing these bindings requires a separate rebuild of the game graph/spawn. The native export physically excludes deleted nodes and renumbers the rest.

Isolated areas can also be applied and saved. First, new nodes get a game graph binding through links to the original grid. Remaining islands are assigned the nearest existing cross table area, and then that binding is propagated within the island. No artificial navigation links are added between an island and the old grid. The cross table distance of an isolated island is an estimate based on the distance to the nearest old node and the island's links; this does not create a route across the gap. Existing cross table entries are kept.

## Binary storage and reloading

The original `level.ai` contains `hdrNODES`: version, node count, cell size, vertical scale, bounding box and GUID. The loader supports versions 8, 10, 11 and 13. Links in versions 8/10 are packed into 23 bits, version 11 into 25, the runtime representation/version 13 into 26. The plane normal takes a `u16`; the height is also a `u16`. X/Z use the cell number `x * row_length + z`; the height is unpacked through `size_y` and `aabb.min.y`.

The runtime patch `level.ai.editor` stores:

1. `u32` magic `AIG2` (`0x32474941`); old `AIG1` patches are read without a deletion mask.
2. The GUID of the original level and the GUID of the game graph.
3. `hdrNODES` of the working grid, keeping the GUID and version of the original grid.
4. `count` records of `LevelGraph::CVertex` in runtime format, with stable IDs.
5. `count` records of `IGameLevelCrossTable::CCell`.
6. `count` bytes of deletion mask (0: node active, 1: deleted).

The patch is loaded after the cross table is selected and before validation/building of the AI caches. GUIDs, sizes, version, coordinates of old IDs, links and cross table entries are checked. A corrupted or incompatible patch is ignored with a message in the log. Saving first writes and verifies a temporary file; the previous patch is copied to `.bak` and verified before the final file is written. After the file is closed, the write is registered in FS synchronously, without waiting for the file watcher. The final file is compared byte by byte; only after success is the temporary file deleted. On error, `.tmp`/`.bak` are kept, and restoring the previous file is also verified. The exact path is shown in the editor window and written to the log after a successful save.

The original `level.ai` is not replaced by a regular save. This keeps the game graph, spawn, patrol points and saved NPC IDs consistent. After nodes are added, binary search uses a separate sorted index; the IDs themselves are not renumbered. To return to the original grid, remove `level.ai.editor` and reload the level.

Rendering uses a cache of node corners, 16×16 metre spatial blocks, a distance limit and frustum culling. Geometry is submitted in batches sized to the `UIRender` vertex buffer capacity in `OnRenderPPUI_main`, before the scene is drawn into ImGui. The brush has a bright outline and keeps its preview when the cursor misses the surface; painting nodes requires a real hit on the surface. Level Inspector resets its own AI grid cache when `EditorRevision` changes, waiting for the background task before clearing.

## Shared save files

**Overwrite save**, together with the runtime patch, creates next to the level:

- `level.ai.compiled`: the version of the current level grid (8/10/11/13), sorted by packed X/Z, with all links renumbered following the `xrAI/compiler_save.cpp` algorithm; a new GUID. The node size is 21/23/24/25 bytes respectively. The link width, the sentinel for a missing link, the available cover fields, the plane, coordinates and the reserved bits of the original nodes are kept. An unknown version is not converted automatically.
- `build.aimap.editor`: only when the SDK can store the version of the original grid: SDK v1 for AI v10 (24-bit links), SDK v2 for AI v11 (32-bit links), version/box/params/nodes chunks, packed normal and `SNodePositionOld`. For AI v8/v13 this xrAI has no matching mode; the native grid and remap are exported without creating an incompatible SDK source.
- `level.ai.compiled.remap`: `u32 count`, then `count` `u32` values: working ID → ID in the compiled file; `0xffffffff` for deleted nodes.

For the SDK, export requires global alignment of cells and coordinates within `s16`; if this condition is not met, the native export remains available. To use the export in the regular SDK cycle, copy the created `build.aimap.editor` to `build.aimap`, then compile the AI and rebuild the game graph/cross table/spawn. Version 8/13 requires a compiler that supports exactly that version. You cannot simply replace `level.ai` with `level.ai.compiled`: sorting changes the IDs, and the new GUID deliberately signals that dependent data must be rebuilt.

`Overwrite save` keeps the GUID/version of the original grid in the runtime patch and checks the limits of the original format on apply and save. If the record size of the original `level.ai` does not match the known layout for the stated version, apply/save/export are blocked instead of trying to guess the mod's format. `level.ai.editor` is this editor's own format, not a standard file for third-party engines. Compatibility with a third-party engine is provided by the native export of the matching version.

Brush generation checks that the surface supports the cell, the slope and the directed climb/descent limits, as well as static obstacles at body heights. This is a runtime generator, not a full SDK motion simulator. New nodes do not get a full offline calculation of cover coefficients: that requires the export and xrAI.

## Post-build checks

The editor is released in `CGamePersistent::OnAppEnd` before the render device is destroyed; the `CGamePersistent` destructor also performs a second, safe cleanup. This removes the frame callback and releases the grid/brush shader. The static owner stays empty when `xrGame.dll` is unloaded.

1. Paint an area on the ground and on a slope; check radii of 0.5 and 10 m and the brush passing through bushes.
2. Turn off several directions of a node manually, then brush over it: the directions must be regenerated. Manual outgoing links of neighbouring old nodes outside the stroke are kept; when a new node is added, joining the boundary to the old grid is allowed.
3. Check two floors in one X/Z column: selection and generation must work at the right height.
4. Apply the edits, then delete part of the grid with RMB, apply again and check that the deleted nodes/links are gone. Apply edits with live NPCs, check route finding over the new area and after disabling a direction, as well as behaviour near restrictors/smart covers.
5. Save, reload the level, make sure nodes/links are restored. Then change another area, apply and save again.
6. Save with the shared button, check the compact native export and the SDK files in a separate copy of the level. Check reverting to the save, applying again, and deletion after a reload.
7. Open the editor, turn on the brush/grid display and exit with Alt+F4. Repeat after closing the editor window and after leaving the level to the menu: the shader must be released before the render device is destroyed.
