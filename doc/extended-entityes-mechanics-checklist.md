Это реестр требований и первичная статическая сверка, а не заключение о готовности игры. Сборка и игровые проверки агентом не выполнялись. Непрерывность движения и попадания летунов пользователь сообщает как сломанные; прежние оценки «90% исходников» не являются приёмкой механик.

## Как пользоваться

- **Код** — найден конкретный путь исполнения. Работоспособность в игре ещё не подтверждена.
- **Расхождение** — чтение реализации выявило отсутствующее или отличающееся правило; исправление обязательно.
- **Риск** — найдено условие, способное нарушить механику; требуется воспроизводимый тест/дальнейшая трассировка.
- **Сверить** — подробный перенос пока не доказан. Нельзя заменять этот статус на «Код» по одному имени класса.
- `[ ]` в сценариях — открытая игровая приёмка. Закрывать только с результатом, секциями существ, сценой и режимом команд. Статическую правку не считать игровым успехом.

Все пути C++ ниже относительны `src/xrGame/ai/ExtendedEntityesLogic/`, кроме явно помеченных штатных файлов. При исправлении обновлять строку механики, связанные дефекты и сценарии; сохранять причину изменения. Новые регрессии добавлять сюда, а не терять в журнале беседы.

## Общий контракт Ground и Flying

**Воздух и земля не являются разными экосистемами знаний.** В обеих категориях одинаковы правила интереса/испуга, выбора противника, доверия источнику, последней известной точки, следа, сроков подхода и поиска. Конкретный профиль может отключать способность или менять её параметры; категория сама по себе не меняет смысл знания.

```text
Звук -> услышанная позиция -> интерес / испуг
                                 |
                                 +-> проверка места -> конечный поиск -> завершение

Собственное зрение / разрешённый контакт / урон / сарафан -> знание о противнике
                                 |
                                 +-> подтверждённая цель -> сближение -> достижимая атака
                                 +-> потеря цели -> последняя точка -> след -> конечный поиск
                                 +-> новое обнаружение -> возврат к сближению/атаке
```

Общее состояние должно содержать причину, ID цели/стимула, подтверждённую позицию и время, разрешение живого слежения, срок и прогресс действия. Исполнитель категории выбирает допустимый путь и манёвр: Ground по поверхности/графу, Flying в объёме. Отличаются способ подтверждения достижения места, поза осмотра и контакт атаки; не должны отличаться правила начала/конца исследования. Слуховой интерес не равен зрительно подтверждённому врагу.

Разделение ответственности при исправлении:

| Область | Владеет | Не должна делать |
| --- | --- | --- |
| Общие `Perceptions/` | Факты, их возраст, слуховой интерес/испуг, отношения и доставка знаний | Управлять путём Ground/Flying или раскрывать скрытые координаты обычной цели |
| Общая политика исследования/поиска | Переходы подход→проверка→поиск→завершение, общий смысл результата и срока | Содержать касты по всем видам или строить траектории за категорию |
| Менеджер категории | Выбор схемы и её жизненный цикл | Подменять исследование точки бесконечной атакой/орбитой |
| Схема категории | Физическое исполнение общего намерения, манёвр, локальное восстановление | Заводить независимые правила памяти и передачи врагов |
| Навигация и бюджеты | Снимок, ограниченный расчёт, сертификация, результат/отмена | Останавливать активный пригодный путь только из-за подготовки следующего |
| Debug | Снимки состояний, причины отказов, отрисовка и измерения | Изменять знания/цели либо скрывать отказ планирования подписью «Полёт» |

Это целевой контракт. Отдельного общего автомата исследования в текущем коде пока нет. Не создавать второй общий реестр врагов в категории или бюджетах. Не переносить весь наземный алгоритм в базу полёта копированием: сначала выделить общие решения, затем подключить исполнителей через существующие контракты.

## Найденные расхождения и порядок исправления

| ID | Приоритет | Доказательство / действие |
| --- | --- | --- |
| D01 | 1 | **Разное поведение по одному знанию.** Ground.UpdateTarget выбирает SearchBehavior после достижения скрытого места. Flying.ChooseBehavior при любой Observation выбирает AttackBehavior; ChooseGoal запрещает Dive без CanSee и переводит в Exit. Нужен общий выбор «подтверждённая цель / известное место / след / поиск», затем исполнитель категории. Не лечить постоянным разрешением живых координат |
| D02 | 1 | **Устаревший AimPosition.** Flying.RefreshTarget при !CanSee возвращается без принятия новой позиции того же ID из SetObservation. Ground использует свежее Observation.Position и явно учитывает live/visual grace. Нужно согласовать семантику знания и позицию контакта, не раскрывая скрытую обычную цель |
| D03 | 1 | **Самоотмена коррекции/устаревание подхода.** CorrectDive отменяет pending/готовый путь, сохраняет до speed×lookahead старого участка; Approach никак не корректируется в исполнении, проверяется только при принятии. Измерить возраст снимка и остаток пути, связать метаданные с запросом, исключить отмену новой коррекции следующим тиком до результата |
| D04 | 1 | **Нет гарантии пересечения тела.** RootAtContact рассчитывает yaw-only offset. Добавлены обязательная горизонтальная касательная контакта, выравнивание крена относительно контакта и проверка сегмента после движения в системе цели. Полный вращательный sweep тела и фактические попадания ещё требуют игры (T30/T32). Не увеличивать радиус урона для маскировки |
| D05 | 1 | **Отладочная цель не равна активной.** BehaviorBase.Goal хранит следующее назначение; DebugGoal показывает его во время прежнего участка. Раздельно показывать активную фазу/контакт и следующий маршрут, плюс причину запрета Dive. Красный индикатор сам по себе не доказывает попадание |
| D06 | 2 | **Порог зрения начисляется по вызовам Observe.** HasVisualAcquired использует время вызова и CanSee, без номера новой native vision-пробы; историческое правило требует начисления только по новым подтверждённым замерам. | D07 | 2 | **Периферийный поворот Ground используется для Flying.** face_target не обязан менять полётный XFORM/eye_matrix при отключённом наземном движении. Ввести исполнение внимания категорией через согласованный контракт, не добавлять врага через стену |
| D08 | 2 | **Критерий достижения места упрощён.** Ground.UpdateTarget: расстояние+check_position_in_direction; исторический критерий дополнялся высотой AI-плоскости и коротким статическим лучом. Проверить стену/этаж/склон; воздушный критерий также должен подтверждать возможность осмотра места, а не только XZ |
| D09 | 2 | **Поиск упрощён и отсутствует в воздухе.** Ground.SearchBehavior повторяет пять углов одного радиуса. Нужны общий конечный сценарий поиска по направлению следа и расширение; специфична только проекция/навигация |
| D10 | 2 | **Стратегии требуют сверки смысла.** Retreat в текущем коде уже проверяет !NearbyCount и низкое здоровье, но уходит на 8 м от цели без выбора союзника. Encircle использует ID%5 вместо ранга группы; GatherPeers рассматривает первые 32 владельца. Сверить большую/смешанную стаю, не путать с полным подсчётом в SharedTargets |
| D11 | 2 | **Часть настроек Ground не подключена.** monster_enemy_stuck_time отсутствует в чтении, Validate жёстко 3000. monster_search_animation не читается; Inspection использует только eAnimSniff. Восстановить конфигурируемые настройки и fallback без отсутствующих анимаций |
| D12 | 2 | **Не весь старый профиль вороны имеет доказанную замену.** Range динамически читает _min/_max — простой grep даёт ложные потери. Но отдельные ключи вроде crow_noise_memory_time и семейства shelter_check_time не покрыты текущим Load. Составить явное соответствие «старый ключ → новый ключ/потребитель/осознанно удалено», затем менять конфиги и empty_example вместе |
| D13 | 2 | **Срочная передача собственного обнаружения отсутствует.** В текущем Sharing.Update нет сигнала нового собственного зрения и ускорения NextSession. Вернуть согласованное одно срочное сообщение с квотой/защитой от каскада, сохраняя обычные интервалы |

Сначала закрыть D01/D02 и фактический переход в налёт, затем D03/D04 и контакт по движущейся цели, параллельно D05 для диагностики. ## Игровая приёмка

Для каждого пункта записать: сборка, уровень, секции/число участников, конфиг, `monster_logic`/`ai_ignore_actor`, наблюдаемые фазы, изменение здоровья, причины отказов. Одинаковые правила повторять на Ground и Flying, затем на смешанной группе. Проверку выполняет пользователь после своей сборки.

- [ ] T01. Off/on/config до спавна и в погоне; обычные виды возвращаются к ванили. Новые летуны имеют явно определённое безопасное состояние off.
- [ ] T02. Видимый неподвижный наземный противник и один сильный летун в открытом месте: обнаружение → снижение → красная фаза контакта → реальная потеря здоровья → выход. Не засчитывать пролёт в 1–2 м над телом.
- [ ] T03. Та же цель бежит/меняет направление/высоту; контакт на актуальном теле, а не на старом грунте. В debug различимы активный контакт и следующий план.
- [ ] T04. Потеря зрения за стеной: обычный Ground и Flying проверяют сохранённое место, используют подтверждённый след, ищут конечное время и прекращают. Скрытый уход не дорисовывает след.
- [ ] T05. Новое зрение во время подхода/поиска/осмотра: возврат к преследованию без перезапуска всей памяти; повтор старого сарафана не возобновляет законченный поиск.
- [ ] T06. Пси и обычный вид с одинаковым скрытым противником: live/wireless независимы. PseudoDog остаётся обычным; PsyDog/фантомы — пси.
- [ ] T07. Короткие появления ГГ за щелью и длительное появление; отдельно NPC/мутант, которому порог ГГ не применяется. За стеной близость не подтверждает зрение.
- [ ] T08. Два профиля с разным разрешением листвы: куст прозрачен только разрешённому; стена непрозрачна обоим.
- [ ] T09. Один и повторные выстрелы, глушитель, пять классов оружия, пять режимов шагов, прыжок, нож, взрыв: проверить границы радиуса/накопление/спад/списки.

### Изменения после первичной сверки, 19.10.2026

В код внесены частичные исправления D02/D03/D05: известная позиция того же ID принимается и без нового зрения; готовый следующий боевой путь проверяется до конца текущего; ожидающая коррекция защищена от повторной отмены; debug показывает активный конец пути, центр тела, покадровую причину и отдельный режим [АТАКА]. Исчезновение подписи из-за CanControl устранено на уровне публикации. Recovery разрешает заранее перейти к следующей схеме, сохраняя безопасный остаток пути. Эти изменения не закрывают D01 и весь контакт D04.

F04 расширен до шести конфигурируемых фигур, F05 — ограничение скорости по кривизне и темпа изменения pitch; F18 — декоративный отдых только без целей/стимулов, с отменой при их появлении. GuidePoints проходят общую worker-математику и сертификацию, полная петля использует консервативный габарит вращающегося тела и Fquaternion. Новые параметры добавлены в четыре профиля и empty_example. Внешние ванильные классы в этом проходе не менялись. Гарантия плавного стыка Ground по XZ и Flying по XYZ остаётся общей приёмкой, а не разрешением сглаживать путь через геометрию. Все T01–T23 открыты до игры; атака и отсутствие зависаний пока не объявлены исправленными.

## Уточнение по зависанию при обходе, 19.10.2026

По скриншотам воспроизводится остановка в поиске воздушного коридора и восстановлении. Исправлен повтор прямого маршрута внутри обхода: после отказа кривой граф больше не принимает ребро старт–цель без промежуточного узла. Недопустимые конечные точки (за воздушными границами или внутри запретной сферы при старте снаружи) отклоняются до полного поиска. Сертификация итоговой кривой и общий бюджет сохранены. Это устраняет конкретный цикл повторных отказов, но непрерывность движения и успешный выход из всех препятствий ещё требуют проверки в игре; D03 и D04 не закрыты.

Подписи известных аномалий сгруппированы по наблюдателю в одну строку ID через запятую; повторные шейпы одной аномалии устранены в общей отрисовке.

## Повторная сверка всех схем и взаимных атак, 19.10.2026

**Итог: все схемы пока нельзя считать правильными.** Ниже проверены конкретные реализации и связи между ними. Статус «исправлено в исходниках» означает статическое исправление, а не успешную сборку или приёмку в игре. Новые сообщения пользователя подтверждают сохраняющийся дефект налёта: краткий красный индикатор, затем ожидание коридора и нулевая скорость.

### Схемы и их жизненный цикл

Все перечисленные схемы реализуют IELBehavior непосредственно либо через базовую схему; общий менеджер вызывает Enter/Update/Validate/Recover/Exit. Наличие этих методов само по себе не доказывает правильный переход или прогресс.

| Реализация | Что проверено | Результат / оставшееся нарушение |
| --- | --- | --- |
| Ground/Behaviors/CELGroundReactionBehavior | Интерес, паника, выбор доступной точки, срок реакции, осмотр источника | Общий слух используется; паника старше обычного интереса. При интересе после достижения выполняется стоячий осмотр до Until, полноценного общего конечного поиска вокруг шума нет. Это расхождение с требованием одинакового исследования Ground/Flying, а не зависание свободного движения |
| Ground/Behaviors/CELGroundBodyBehavior | Claim тела, подход, осмотр, ограничение времени, Release в Exit | Путь исполнения есть. Пределы подхода/осмотра частично числовые константы; точность достижения тела по высоте/преграде не доказана. Не смешивать событие тела/опасности с аномалиями |
| Ground/Entityes/Aggressive/Behaviors/CELGroundAttackBehavior | Сведения о цели, видимый/разрешённый live-подход, срок подхода, передача Move | Сам удар выполняет штатная FSM после решения CELGroundAttackBase. Сохраняются D08/D10/D11/D14; native special attacks нельзя считать покрытыми одним расстоянием до цели |
| Ground/Entityes/Aggressive/Behaviors/CELGroundSearchBehavior | Срок, направление следа, пять точек веера, осмотр | Конечный поиск есть, но расширения радиуса и общего сценария с Flying нет (D01/D09). При смене поисковой точки путь сбрасывается; непрерывный переход не доказан |
| Flying/Behaviors/CELFlyingCruiseBehavior | Блуждание, шесть фигур, интерес/испуг, безопасные кривые | При интересе используется облёт точки до срока общего слуха, не эквивалент наземному осмотру/поиску. | Flying/Entityes/Aggressive/Behaviors/CELFlyingRecoveryBehavior | Ограниченные попытки, выход из препятствия, ранний возврат к следующей схеме | Есть конечные попытки и общий контроль продвижения. Выбор выхода снова после исчерпания попыток может повторять неудачный цикл; безопасное непрерывное продолжение при отказе всех направлений не доказано |

Между посадочными фазами остаётся ожидание планового обновления/расчёта. Это посадка, а не право зависать при налёте |

| Flying/Entityes/Passive/Entityes/Crows/Behaviors/CELCrowLandingBehavior | Две посадочные фазы, проверка маршрута, срок/прогресс, очистка | Все этапы есть; следующий посадочный участок не готовится до завершения активной фазы. Приёмка посадки/прерывания угрозой открыта |

CELGroundApproach — помощник выбора стратегии, а не самостоятельная IELBehavior. Пассивная ворона может быть целью врага по отношениям игры, но сама не начинает бой.

### Конкретные исправления этого прохода

- При потере обзора текущий сертифицированный Dive не отменяется и не укорачивается ради Exit. Завершается сохранённый пролёт; новые скрытые координаты не читаются, TryHit без актуального зрения не вызывается. Подготовленный Dive разрешён как путь к известной точке, но сам путь не разрешает урон.
- Более старая плановая Observation того же ID не затирает последний собственный покадровый визуальный отсчёт. Новое подтверждение того же врага может обновить знание; при смене ID отметка собственного зрения сбрасывается.
- Цель удерживается только на исполняемом Approach/Dive и только пока есть её запись памяти и живой допустимый противник. SelectTarget вызывается из Observe до PublishNativeMemory и штатного EnemyMan.update; Flying.Update больше не делает независимый второй выбор. Распределение между союзниками остаётся общим; после захода снова работает SharedTargets. Смерть, ignore actor и утрата записи отменяют фиксацию.
- CanPursue отделён от IsEnemy и CanReach: враг может оставаться известным, но не подходить для преследования. Высотный фильтр применён и к удержанному назначению, и к новым кандидатам, и к native EnemyMemory, чтобы штатная FSM не обходила его. Новых высот/прыжков в конфигах не выдумываем: используются уже существующие jump_max_height и MeleeChecker.
- На Ground заполнено поле скорости через movement().speed(); прежнее постоянное «0 м/с» было также дефектом debug, а не доказательством физической остановки. Поле показывает штатную скорость менеджера движения, не отдельный физический профайлер.
- Израсходованный воздушный путь больше не публикуется покадрово как «Подготовленный маршрут»: выводится только исполняемый путь, с соответствующей подписью. Короткий остаточный TTL уже опубликованного события по-прежнему принадлежит общей отладке.
- События аномалий отделены от общей опасности тела: список «Известные аномалии» не должен включать ID погибших монстров.

### Регрессия резервных кругов: повторная сверка всех типов

Игровая проверка пользователем опровергла достаточность прежнего исправления: резервный круг повторялся бесконечно, атаки были редкими, на концах участков наблюдалось торможение. Цель впереди — допустим прямой контактный заход; позади — разворот на выбранную сторону; пауза удара — конечный выход; отказ — другая сторона, затем ограниченное восстановление. Это суммарные счётчики мира, не время лучей и не FPS. Дополнительный пересмотр решений и более плотная обработка доступной квоты могут увеличить фактическую работу CPU; частота кадров в игре не замерена. Новых потоков нет; A* и построение кривых остаются на существующем seqParallel, RayQuery — в игровой фазе. Исходные классы движка/ванильных монстров не изменены.

- Исправлено продвижение курсора при отказе в квоте в геометрии, воздушном/наземном захвате и фоновом A*: необслуженный запрос остаётся первым на следующую порцию. Раньше cursor++ перед проверкой бюджета мог постоянно пропускать один и тот же остаток очереди. Модель с тремя запросами и двумя операциями на кадр воспроизводит голодание третьего до исправления; после исправления запросы обслуживаются равномерно.

- Дешёвые попадания в кэш и отбрасывания по границам больше не расходуют квоту новых геометрических проб. Воздушный захват имеет собственную общую порцию времени между повторными вызовами кадра (примерно 500 мкс при исходных настройках); он может продвигать известную карту и после исчерпания лучей. Повторный проход прекращается, если ни очередь захвата, ни геометрия не продвинулись.

- [ ] T46. Холодный/повторный поиск в двух комнатах и проход из улицы: несколько летунов, источник звука и цель без AI-сетки. Сравнить задержку, STALL, air_cache_hits/misses и загрузку кадра. Повторить с узкой дверью, разными этажами и размерами тел.
- [ ] T47. Движущаяся цель, повторные шаги/выстрелы, появление нового видимого врага при скрытом старом: готовый поиск не должен непрерывно отменяться, а выбор тактики — ждать окончания старого поиска. Проверить также наземные подход, поиск и передачу атаки штатной FSM.
- [ ] T48. Уход всех владельцев из области, сохранение области при остающемся владельце, достижение лимитов кэша, переход уровня. Статические модельные проверки не заменяют этот игровой прогон. Полное отсутствие остановок пока не подтверждено.

- [ ] T49. Проверить целевой срок выбора следующего действия до 500 мс при одиночном летуне и стае: отдельно холодная/известная геометрия, движущаяся цель за дверью, блокированный проход. Учитывать фактическое начало движения и request_age_ms/route_ready_ms, а не только переключение подписей. Этот срок пока не подтверждён игровым замером.

Текущий общий лимит воздушных геометрических лучей — 350 за кадр: значение задано в конфигурации аддона и обоих значениях по умолчанию движка. Подсчёт 94 STALL выше относится к прежнему лимиту 192. Основной игровой прогон — 20–50 летунов в бою; 500 одновременно активных — отдельный нагрузочный сценарий. Суммарная популяция до 2500 онлайн/офлайн не равна числу одновременных потребителей геометрии. Дополнительный поток для статических лучей этой правкой не вводится. Сохранение незавершённой заявки при отдельном манёвре отлёта и обратная стыковка пока не реализованы; готовность маршрута за 500 мс и полное отсутствие остановок не подтверждены.

### HUD производительности и онлайн-популяции

- monster_debug_hud on показывает живых онлайн-летунов и прочих CBaseMonster из Level().Objects, без фильтра видимости камеры и без зависимости от включения расширенного поведения. Мёртвые и удаляемые экземпляры исключены; офлайн ALife не входит в список клиентских объектов. CELDebugOnlinePopulation выполняет один проход раз в 250 мс только при включённой отладке.
- Для групп и общей суммы выводятся миллисекунды последнего завершённого кадра / пик / среднее. Срез отстаёт на два кадра, окно до 118 кадров. Для каждой стадии и группы отдельно выводятся кадр / пик: восприятие, поведение, движение, слух, обмен, мировые службы, worker A*/кривые, захват графа, геометрия. Вложенные интервалы вычитаются из родительских; пик группы считается по сумме одного кадра, а не сумме пиков разных кадров.
- Это CPU расширенной логики, а не стоимость всего штатного ИИ/рендера или GPU. Прямые проверки локальной высоты и посадки и очередь подвижных препятствий отнесены к воздушной геометрии. Общий код очереди worker остаётся в общих службах. В выключенной статистике новые таймеры не запускаются. Визуальное размещение HUD и цена профилирования требуют игрового прогона.

### Непрерывный цикл letalka и порядок захвата коридора

В meshes/monsters/letalka/letalka.ogf непосредственно проверены параметры движений: stand_run_0 имеет esmStopAtEnd (flags=2), speed=1. Поэтому обычный PlayCycle завершал полётную анимацию после одного проигрывания. ExtendedEntityesFlightAnimation::PlayLoop запускает выбранный полётный цикл с noloop=false через штатный LL_PlayCycle, сохраняя часть скелета, скорость и параметры смешивания. Общий CMotionDef и файл модели не меняются. Применено к спавну, выбору полётной анимации и замене отсутствующего цикла. Отдельные настроенные анимации атаки сохраняют прежнее воспроизведение.

В CELSharedFlyingGraph узел сохраняет NextEdge. После каждой завершённой проверки можно выбирать ближайшую к цели незавершённую ветку (дистанция + 0.01 цены), не дожидаясь проверки всех шести соседей предыдущего узла. Незавершённые ветки сохраняются; тупик позволяет вернуться к ним. Каждая пара узел/ребро проверяется не более одного раза на захват. Worker A* и финальная сертификация сглаженной кривой сохранены. На 200 модельных полях препятствий достижимость совпала с предыдущим полным раскрытием; для отдельного поля со стеной и смещённой дверью количество проб 673 -> 495. Это модель порядка обхода, не игровой замер лучей или задержки. AI-сетка не используется воздушным захватом; игровой результат и отсутствие длительных STALL в помещениях ещё нужно подтвердить.

### Непрерывность движения: общие очереди, блуждание, след и бой

- CELFlyingContinuity подключён к общей CELFlyingBehaviorBase: до конца пути (примерно за секунду по длине/скорости) готовится отдельный короткий манёвр. Его вычисление не отменяет основной поиск. Когда обычное продолжение опаздывает, в оставшееся время кадра принимается готовый ближний участок. Отдых/посадка и внешнее управление исключены. При фактической скорости ниже 0.2 м/с дольше 300 мс допускается проверенная замена из текущей позиции, а не ожидание прохождения вырожденного виража. Сокращение пути при торможении не сбрасывает этот таймер.
- Первый манёвр — дешёвый почти прямой отход; остальные — короткие гладкие варианты с ориентацией относительно назначения, смещением в сторону/по высоте и проверкой всего тела. При прерывании переворота сохраняется увеличенный радиус тела. Результат не становится полётом без проверки: центральный/угловые статические лучи, пол/потолок, динамические тела и известные опасности остаются обязательными.
- Общий аварийный запас — максимум +96 лучей за кадр сверх обычных 350, не на каждого владельца. Мягкий предел дополнительной порции — 300 мкс: проверка короткого кандидата атомарна, поэтому один допущенный кандидат может превысить временной порог; лучевой предел остаётся жёстким. Центр проверяется одним лучом до резервирования остальных 29 на один отрезок. У короткой кривой три отрезка, максимум 90 зарезервированных лучей, включая динамику и выход из исходного углового касания. Фоновая трассировка статики этой правкой не добавляется.
- Готовый ответ старого поиска можно состыковать к ближайшему подходящему узлу через вновь проверенную кривую. Обязательный контакт налёта и потоковый конец сохраняются; прямого переноса сущности на прежний старт нет. Несостыковавшийся устаревший ответ удерживается до 2 с, затем допускается перепланирование. Идентификаторы всех полётных планов теперь выдаёт один счётчик владельца, включая воронью посадку и ближние манёвры. Ближний манёвр помечается отдельно и не разрешает удар/красное состояние атаки; формула попадания не менялась.
- Корневое ограничение очереди геометрии изменено: вместо половины квоты оставляется резерв min(64, квота/4) для постановки запросов/локальной высоты. При лимите 350 геометрическая очередь может использовать до 286 вместо 175 лучей (при наличии остатка и времени). Динамически заблокированные коридоры перепроверяются; прежний skip делал блокировку постоянной до смены маршрута. Отказ в бюджете возвращает курсор к необслуженному коридору. После освобождения препятствия снимается торможение.
- Захваты воздушного графа, геометрическая очередь и общие worker-заявки освобождаются при исчезновении/смерти владельца или несовпадении поколения. Живые объекты проверяются в игровой фазе; worker по-прежнему работает с собственными данными. STALL-лог дополнен continuity, stalled_route, emergency_rays_left без повышения частоты сообщений.
- Проверены модели общего резерва (10000 последовательностей), ограниченное повторное обслуживание коридоров, удаление элементов с курсором, 1000 стыков с обязательным контактом и статические условия исключения отдыха/урона. Это не запуск C++ и не игровой тест. Полное исчезновение остановок в бою, блуждании и поиске по следу остаётся обязательной игровой проверкой. При отсутствии физически проходимого ближнего манёвра непроверенный полёт не исполняется.

## Проверка чувств и наземного поиска (20.10.2026)

- 3D-отладка показывает подтверждение зрения актора с давностью, источник памяти, таймер памяти, активный звук с ID источника, приоритетом и оставшимся временем поиска. Подтверждение зрения не вычисляется заново ради отладки.
- Оранжевая подпись «Зрение: игнорирует растительность» означает включённую способность профиля. Прозрачны только разрешённые материалы листвы; стены этой настройкой не отключаются.
- Серые кольца звуков игрока живут 250 мс и расположены на высоте позиции игрока +0,3 м в момент события. Разные профили слуха дают разные кольца. Отметка «Услышал игрока» появляется после реальных проверок слуха, а не только нахождения внутри нарисованного круга.
- Обычные звуки дружественных монстров исключены из слуховой реакции, независимо от разрешения обмена сведениями. Клич и обмен знаниями продолжают работать отдельным каналом. «Голос / вокализация» соответствует `SOUND_TYPE_TALKING`, включая `SOUND_TYPE_MONSTER_TALKING`.
- Приоритет активного слухового исследования удерживается до его завершения; равные и меньшие стимулы не меняют точку поиска. Выстрел имеет приоритет 80, опасность 100, прочий шум 10. Услышанный источник проверяется бегом; недоступная точка заменяется доступными пробами вокруг неё, а затем расширяющимся поиском.
- Наземный локальный обход вынесен в `CELGroundLocalSearch`: он не отменяет основной поиск, проверяет АИ-сетку, известные опасности и статическую коллизию, расходует общий бюджет геометрии. Отсутствие сетки не означает разрешения идти сквозь стену. Физически закрытое место не гарантирует прохода.
- Свидетель смерти союзника проверяет видимость жертвы и убийцы отдельно. Скрытый убийца не раскрывается: расследуется место гибели. Видимый противник фиксируется на время поиска. Проверки используют существующий бюджет зрения.

### Настройка в секциях аддона мутантов

`monster_behavior_schemes = close_scent` разрешает отдельную схему `CELGroundCloseScent`; дополнительного флажка и списка видов в C++ нет. Схема включена конфигами семейств собак, баюнов, волков, медведей, химер и псевдособак. Её можно добавить любой другой наземной секции, включая наследование.

| Параметр | Значение / смысл |
| --- | --- |
| `monster_close_scent_radius` | 3 м у слабых вариантов, 5 м базовый, 7 м у сильных; радиус настраивается в секции |
| `monster_close_scent_time` | 5 с; обновляется только реальным зрением в пределах радиуса |
| `monster_noise_search_time` | 60 с от принятия стимула; настраивается в секции |
| `monster_noise_shot_priority` | 80 |
| `monster_noise_danger_priority` | 100 |
| `monster_noise_other_priority` | 10 |
| `monster_noise_expand_search` | true; переход к поиску вокруг источника |
| `monster_search_time_min` / `monster_search_time_max` | 45–60 с поиска по последней известной точке |
| `monster_enemy_memory_min` | 60 с минимального удержания знания, без обновления скрытой позиции |
| `monster_body_inspect_time_min` / `monster_body_inspect_time_max` | 3–6 с осмотра тела |
| `monster_search_point_time` | 3 с на очередную пробу поиска |
| `monster_ground_local_retry` | 0,2 с между ограниченными локальными пробами |

Чутьё допускает обновление скрытой позиции только после близкого зрительного контакта, до истечения таймера и пока цель не вышла из радиуса. Слух, клич, урон и само чутьё таймер не продлевают. Выход из радиуса отменяет допуск до нового близкого зрительного контакта. Белая сфера и отдельная строка с целью и остатком времени показываются только при активном допуске. Пси-слежение `monster_enemy_tracking_live` помечается отдельно; общий прежний доступ к живой позиции через `VisualGraceUntil` отключён.

Сборка и проверка в игре для этих изменений ещё не выполнялись.

Пси-передача сведений о противнике помечается синим цветом. У получателя сохраняются ID и поколение фактического отправителя конкретного наблюдения. Пока выбранная цель известна из этой пси-передачи и отправитель жив, 3D-отладка рисует синюю связь по текущим позициям и подпись «ПСИ-НАВЕДЕНИЕ ОТ #ID». Личное наблюдение, смена источника, удаление отправителя или истечение памяти прекращают такую отметку. Дополнительные лучи зрения для неё не выполняются.

У всех нативных летунов аддона и обеих ворон `monster_vision_ignore_foliage = false`, включая наследуемые варианты.
