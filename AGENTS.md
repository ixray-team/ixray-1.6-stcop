# Правила работы с репозиторием

## Язык

- Внутренний технический анализ и обдумывание выполнять на английском языке.
- Все сообщения пользователю, отчёты, планы, статусы и документацию писать на русском языке.
- Новые и изменяемые комментарии в коде писать на русском языке.
- Идентификаторы C++, HLSL, CMake и имена файлов сохранять на английском языке согласно code style проекта.
- Исходный текст диагностик, API и сторонних инструментов разрешено оставлять на языке источника, но вывод по ним давать на русском.

## Tiramisu Render

- Игровой R4 сохранять рабочим; Tiramisu остаётся opt-in через `-r5`, пока не закрыты acceptance gates.
- LevelEditor и остальные редакторы целевым образом переводятся на Tiramisu. Старые `.object`, `.level` и OGF поддерживаются как входные данные для автоматической конвертации с дампами.
- Не считать старые build-каталоги доказательством актуальной работоспособности после смены ветки, merge, rebase или восстановления истории.
- Все тестовые executable, editor smoke, GPU tests и automated flythrough запускать с точным аргументом `-rdbg`. Результат без `-rdbg` не закрывает задачу.
- Автоматические LevelEditor smoke запускать через `Start-Process -WindowStyle Hidden` с аргументом `-editor-test-hidden`; прямой GUI-запуск для тестов запрещён, потому что он забирает пользовательский фокус. Флаг использовать только вместе с валидным `-render-deterministic` и `-rdbg`.
- Vulkan и D3D12 проверять как равноправные backend. После Vulkan обязательно выполнять D3D12-проверку.
- Для renderer/editor изменений по возможности выполнять normal и ASan проверки.
- RenderDoc запускать через поддерживаемый аргумент `-renderdoc`; в отчёте указывать backend, версию RenderDoc и наличие validation/sanitizer ошибок.

## Сборка и Git

- Использовать актуальные CMake presets. Устаревший `build2` не считать эталонной сборкой.
- Собирать обычной параллельной сборкой; не использовать `/MP1`.
- Не удалять и не перезаписывать пользовательские изменения, untracked assets, dumps, логи или build-каталоги без явного разрешения.
- Перед staging проверять точный список файлов. Не добавлять посторонние пользовательские изменения в коммит.
- Не создавать коммит, пока пользователь явно не попросит об этом.
- После пересоздания ветки сначала закрывать этап восстановления baseline из документации Tiramisu, только затем продолжать feature roadmap.
