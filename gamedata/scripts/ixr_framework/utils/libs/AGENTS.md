# Библиотеки общего API

Сначала прочитай [общие правила утилит](../AGENTS.md) и [карту Framework](../../AGENTS.md).

Эти библиотеки обслуживают общее API утилит, исходные игровые скрипты, моды и фреймворк. Они доступны через неймспейсы скриптов и не требуют подключения как управляемые модули.

| Скрипт | Публичный вход | Назначение |
| --- | --- | --- |
| `ffx_json_lib.script` | `json_encode(value)`, `json_decode(text)` | Кодирование и разбор JSON; используется, в частности, модулем опций. |
| `ffx_base64_lib.script` | `encode(data)`, `decode(data)` | Преобразование строк/байтов в Base64 и обратно. |

Само обнаружение расхождения не является задачей на изменение скриптов или документации. Минимальную версию проверяй на конкретной странице.

## Правила изменений

- Не пиши второй JSON/Base64 парсер в другом месте проекта. Используй готовую библиотеку и предварительно проверь её реальные сигнатуры и формат результата.
- JSON API называется `json_encode`/`json_decode`; не подменяй его предполагаемыми `encode`/`decode`. У Base64 имена именно `encode`/`decode`.
- JSON-парсер сообщает об ошибке через `error`, а не возвращает гарантированную пустую таблицу. При изменении обработки ошибок учитывай текущих потребителей.
- Сохраняй различия JSON object/array, правила ключей, чисел, строк, Unicode и экранирования. Проверь реальное представление `null` и пустых таблиц; не обещай сохранение пропусков и nil-элементов без проверки реализации.
- Base64 использует стандартный алфавит с `+`, `/`, `=`. `decode` сейчас отфильтровывает символы вне этого алфавита; переход на строгую проверку является изменением поведения.
- Не добавляй исполнение кода, обращения к движку, регистрацию событий или загрузку модулей в парсеры.
- При изменении формата проверь совместимость уже сохранённых опций. Для JSON важны обратное преобразование, повреждённый ввод, числа, Unicode и вложенные коллекции; для Base64 — пустая строка, бинарные байты и длины с остатками 0/1/2.
