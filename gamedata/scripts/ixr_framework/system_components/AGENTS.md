# Внутренние системные компоненты

Общие правила: [корень Framework](../AGENTS.md). Публичные помощники описаны отдельно: [public_components](../public_components/AGENTS.md).

Здесь находятся узконаправленные решения для внутренних нужд фреймворка и оригинальных игровых скриптов. Не превращай внутренние детали в обязательное публичное API для модов без соответствующей задачи.

## Пользовательская документация и примеры

- [Разделение компонентов](../../../../IX-RAY/docs/docs/main/ru/scripting/ixr-framework/components.md)
- [Структура файлов](../../../../IX-RAY/docs/docs/main/ru/scripting/ixr-framework/files.md)

Начинай с документации нужного API и примеров, затем сверяй сигнатуры, значения и жизненный цикл с текущей реализацией. Если старая формулировка расходится с актуальными правилами владельца проекта (например, допускает имя файла модуля вместо alias), соблюдай актуальные правила из родительских AGENTS.md. Само обнаружение расхождения не является задачей на изменение скриптов или документации. Минимальную версию проверяй на конкретной странице.

## `ixr_callback_binder.script`

- `manage_callbacks(script_name, all_callbacks, ref, is_set, use_callback_logs, beforeSetAction, beforeUnsetAction)` устанавливает или снимает движковые callbacks игрового объекта.
- `all_callbacks` сопоставляет имя из движкового `callback` с именем метода биндера. Проверяются наличие callback и метода; на установке создаётся прокси, на снятии передаётся `nil`.
- Это работа с `_ref.object:set_callback`, а не регистрация имён событий шины `ixr_signals`. Не смешивай два механизма.
- Сохраняй вызываемые before-set/before-unset hooks, парность установки и снятия, исходные аргументы и фактическую передачу `self`. Прокси уже получает аргументы от движка; не добавляй экземпляр повторно без проверки стороны вызова.
- Источник логов передаётся явно через `script_name`. Сохраняй возможность отключить подробные логи.

## `ixr_npc_info.script`

- `collect_object_info` собирает сведения о переданном объекте; здесь же находятся `IsWounded`, `arrived_to_smart` и вспомогательные таблицы/функции.
- Проверяй допустимость объекта, наличие его записи в `db.storage`, squad/smart и доступность требуемых методов. Не рассчитывай, что все игровые объекты являются NPC одного класса.
- Сохраняй имена и типы полей результата для существующих потребителей. Общие операции с объектами, векторами и таблицами ищи в [utils](../utils/AGENTS.md).
- Не используй сбор полной диагностической структуры на каждом обновлении объекта ради проверки одного признака.

Новые имена событий шины регистрируются только в `../../__ixr_override_signals_intercepts.script`. Изменения движкового моста проверяются вместе с `../../___ixr_engine_callbacks.script` и оригинальным биндером.
