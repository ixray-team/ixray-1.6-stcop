# Публичные компоненты

Архитектура и общие правила: [корень Framework](../AGENTS.md). Общие повторно используемые алгоритмы: [utils](../utils/AGENTS.md).

Это доступные разработчикам модов компоненты-помощники. Они не требуют регистрации и отдельной инициализации через менеджер модулей; внутри Framework их функции вызываются через неймспейс скрипта. Внешний игровой код использует предусмотренные глобальные обёртки из `global.lua` (например, `IXRLog*` и `PROF_EVENT_*`) либо API, явно предоставленный обратным вызовом. Служебный `on_game_start` или framework hook возможен, но не превращает компонент в управляемый модуль.

Само обнаружение расхождения не является задачей на изменение скриптов или документации. Минимальную версию проверяй на конкретной странице.

## Логирование — `ixr_logs.script`

- Публичное API: `set_use_file_log`, `set_use_console_log`, `set_use_time`, `log`, `empty_line`, `clear_log`, `update`, управление включением.
- Настройки и сообщения разделяются по вызывающему скрипту; `custom_script` позволяет указать источник явно. Глобальные `IXRLog*` обёртки находятся в `../../ixray_system/global.lua`.
- Сохраняй семантику caller lookup и его глубину. Добавленная обёртка может незаметно сменить владельца настроек или имени файла журнала.
- Сообщения для файла накапливаются в `logs_history`, `is_need_flush` сигнализирует о работе для `update`. Не заменяй буфер немедленной записью на диск при каждом сообщении.
- Проверяй отдельное включение файла/консоли/времени, очистку и последующую дозапись. Публичная обёртка и внутренняя реализация должны согласованно передавать источник.

## Карта контекстного («беспроводного») логирования

Пользователь пишет `IXRLog("сообщение")` и настраивает вывод через `IXRLogUseFileLog`, `IXRLogUseConsoleLog`, `IXRLogUseTimeInLog`, не передавая имя своего скрипта каждому сообщению. Обёртки находятся в `../../ixray_system/global.lua`; они делегируют вызовы `ixr_logs`.

Цепочка данных:

1. Публичный метод `ixr_logs` использует явный `custom_script`, если он передан, иначе вызывает `log_system.get_caller()`.
2. `get_caller` использует `ffx_callable_utils.find_caller_source(CONST_TRACE_LEVEL)`, где `CONST_TRACE_LEVEL = 4`. Утилита смотрит стек через `debug.getinfo`, пропускает C-кадры и убирает `@`, `.lua`, `.script` из источника.
3. `logs_options[caller_script_name]` хранит настройки файла, консоли и времени отдельно для каждого источника. `logs_history[caller_script_name]` хранит очередь его сообщений и флаги записи.
4. `to_log` применяет общие и локальные настройки, добавляет временную метку при включении времени, буферизует файловый вывод и передаёт консольный вывод в `ffx_dump_utils`.
5. Движковый `../../___ixr_engine_callbacks.script:on_frame` вызывает framework frame hook, а тот — `ixr_logs.update()`. Если есть изменения, буферы записываются через `ffx_dump_utils.write_to_file_log`.
6. Утилита записи берёт корень из движкового alias `$logs$`, создаёт подкаталог `ixr_framework_logs` и добавляет расширение `.txt`. Компонент передаёт префикс `__log__` и имя источника.

В текущей установке результат находится в `D:/Games/IX-RAY_DEATH_OR_DIE/storage/logs/ixr_framework_logs/`. Примеры существующих файлов: `__log__ixr_framework.txt`, `__log__ixr_module_signals.txt`, `__log__ixr_module_storage.txt`. Путь на диске зависит от `$logs$`; не встраивай абсолютный путь этой установки в код.

Новый буфер источника начинается с `overwrite = true`; после сброса дальнейшие сообщения дописываются. Очистка выставляет флаг перезаписи и очищает накопленные сообщения. Это буферизованный вывод, поэтому отсутствие немедленного изменения файла после `IXRLog` ещё не означает отсутствие сообщения.

Сохраняй глубину вызовов и явный контекст там, где он предусмотрен: перенос вызова в общую обёртку может сменить источник, настройки и имя файла. Для чтения карты системы достаточно исходников и уже имеющихся журналов; не генерируй сообщения и не очищай рабочие логи ради анализа.

## Профилирование — `ixr_tracy_profiler.script`

- Публичные операции: `prof_event_begin`, `prof_event_end`, `prof_event_closure`, проверка подключения. Обёртки `PROF_EVENT_*` находятся в `global.lua`.
- Компонент проверяет Tracy на framework init/frame hooks; у него есть собственный `on_game_start` для служебных настроек.
- При отключённом профайлере `prof_event_closure` всё равно выполняет переданный callable. Не пропускай его и не вызывай дважды ради измерения/описания.
- Сохраняй парность зон, значения возврата и поведение без подключения. Не добавляй дорогой сбор caller metadata на путь с отключённым профилированием.

Для новых событий действует общее правило: регистрация имени только в `../../__ixr_override_signals_intercepts.script`, не в публичном компоненте.
