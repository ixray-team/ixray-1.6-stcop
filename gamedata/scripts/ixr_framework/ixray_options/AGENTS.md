# Настройки команды IX-Ray

Общие правила: [корень Framework](../AGENTS.md). Механика хранения/UI: [модуль опций](../modules/AGENTS.md).

Эта папка содержит настройки самого проекта IX-Ray для команды. Пример для разработчиков модов находится отдельно: `../../example_options/ixr_options_template.script`.

## Пользовательская документация и примеры

- [Полное API опций, пресеты и зависимые настройки](../../../../IX-RAY/docs/docs/main/ru/scripting/ixr-framework/modules/ixr_options.md)

Начинай с документации нужного API и примеров, затем сверяй сигнатуры, значения и жизненный цикл с текущей реализацией. Если старая формулировка расходится с актуальными правилами владельца проекта (например, допускает имя файла модуля вместо alias), соблюдай актуальные правила из родительских AGENTS.md. Само обнаружение расхождения не является задачей на изменение скриптов или документации. Минимальную версию проверяй на конкретной странице.

## Текущий скрипт

`ixray_global_options.script` в `on_game_start` задаёт метаданные страницы через `SetOptionTitle`, `SetOptionAddonName`, `SetOptionScriptVersion`, `SetOptionAuthors`, `SetOptionIcon` и подписывается на `on_init_ixr_options`.

- `switch_draw_vars` переключает показ имён переменных через `_ref.set_draw_variable_names_state(value)`.
- `_g_draw_debug` обновляет `_G.dev_debug`.
- Регистрация контроллов выполняется в обработчике `on_init_ixr_options` через переданный `_ref.register_option` и готовые фабрики. Передача `_ref` и его захват вложенными замыканиями являются явно предусмотренным доступом к API. Не заменяй их получением внутреннего модуля; глобальные Options-функции и API события дополняют друг друга.

## Добавление настроек проекта

- Добавляй сюда опции команды; универсальные контроллы, сериализацию и геймпад дорабатывай в `modules/ixr_module_options.script`.
- Сохраняй уникальные имена переменных и ключи локализации `st_*`. Имена скрипта и опций участвуют в ключах сохранённых настроек.
- Не меняй формат JSON `ixr_options.ixr` ради одной настройки. Для чтения/изменения используй существующие глобальные Options-обёртки.
- Обработчик изменения получает `(group, name, value, is_value_from_code)` и должен корректно работать при применении сохранённых значений, до открытия UI и при ручном переключении.
- Применение настройки не должно повторно регистрировать контроллы, callbacks или требовать покадрового пересоздания UI.
- Для новой опции существующее событие `on_init_ixr_options` уже подходит. Если требуется новое имя события, регистрируй его только в `../../__ixr_override_signals_intercepts.script`.
