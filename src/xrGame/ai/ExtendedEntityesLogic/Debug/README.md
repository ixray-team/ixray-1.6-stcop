# Debug — общая отладка ExtendedEntityesLogic

Общая очередь отладки и консольные режимы; сборку и проверку в игре выполняет пользователь.

Текущие файлы:

- `Debug.h/.cpp` — класс CELSharedDebug; очередь, фильтры и сроки отладки; [MAIN]; потокобезопасная публикация.
- `DebugCommands.h/.cpp` — класс CELSharedDebugCommands; прямая ранняя регистрация из xrRender_initconsole и применение копий режима в BeginFrame; [MAIN].
- `DebugDrawHud.h/.cpp` — класс CELSharedDebugDrawHud; текст и статистика HUD; [MAIN].
- `DebugDrawWorld.h/.cpp` — класс CELSharedDebugDrawWorld; примитивы через HUD().world_prims; [MAIN].

Статус: перенос в процессе, сборку выполняет пользователь. Готовность и оставшиеся механики: [архитектура](../../../../../doc/extended-entityes-architecture.md).

Обработчики в DebugCommands.h не зависят от игрового состояния и используют штатный Save/Status. monster_logic сохраняет on/off/config, draw/stats — on/off; reset статистики не сохраняется как действие. Регистрации при входе на уровень нет. user.ltx вручную не менять.

## Текущий вывод

`monster_debug_hud on` показывает семь коротких строк: заголовок, Ground, Flying, Shared, entity/game phase, worker tasks и TOTAL. Числа — среднее и пик **суммы длительностей за кадр** по последним 118 завершённым кадрам. Нулевые кадры входят в среднее; отображение отстаёт на два кадра, чтобы не читать незавершённую работу.

Замеры используют штатный `CTimer`. Вложенные замеры вычитаются из родителя. Работа навигации помечается стадией Worker и категорией заявки; накладная работа очереди относится к Shared. TOTAL включает обе стадии. Его пик — максимум покадровых сумм, а не сумма независимых пиков. Категории и строки game/worker — две разные группировки одних измерений; складывать все строки HUD нельзя. Game phase означает обновление сущностей и общих служб; Worker — задания `CELSharedNavigationScheduler::Process` на штатном `Device.seqParallel`. Названия не утверждают, что все прочие callbacks движка выполняются физически на render/main OS thread. Новые потоки не создаются. Это длительность участков новой логики, без штатного AI и без стоимости 3D-отрисовки, не оценка падения FPS.

`monster_debug_3d_shapes on` включает ограниченную очередь копий событий (512 записей, 1.5–2 секунды); таймеры принадлежат только Debug. Все примитивы добавляются через `HUD().world_prims` в фазе отрисовки.

| Цвет | Что подтверждает |
| --- | --- |
| Синий | Только услышанный источник: отметка радиусом 0.25 м и луч от слушателя; радиус слышимости не рисуется, имя шума на русском |
| Голубой / красный | Достигнутый порог интереса / испуга |
| Фиолетовый | Успешно принятый сарафан; подпись различает пси-канал и обычную передачу |
| Зелёный | Решение издать клич и радиус близкой передачи через клич |
| Оранжевый | Сохранённый след и последняя известная позиция, без подглядывания за невидимой целью |
| Жёлтый | Точка поиска, исследование звука или закреплённого тела |
| Розовый | Подготовленный маршрут; полилиния берётся из результата навигации |
| Красная область | Известная наблюдателю аномалия и её обходной радиус |

Сфера владельца краснеет в фазе атаки; подпись рядом показывает текущую валидацию поведения. Отсутствующий принятый шум или обмен не дорисовывается искусственно. Непрерывные события одного владельца обновляют запись, а не создают бесконечный след очереди. Для замеров держать `monster_debug_3d_shapes off`, чтобы диагностическая геометрия не меняла нагрузку сцены.

Все подписи HUD, 3D, схем и сообщения отладки — на русском. Идентификаторы C++/LTX и сохраняемые аргументы команд `on/off/config/reset` не переводятся. Заголовок HUD показывает «ГГ: игнорируется / учитывается», чтобы сразу видеть состояние общего фильтра.

При изменении игнорирования общая точка входа адресно удаляет боевую цель через `ForgetTarget`, сохраняя слуховой интерес и мировые отметки. `RemoveObject` применяется к исчезнувшим объектам. Выстрелы, шаги и взрывы ГГ слышны и при `ai_ignore_actor`, но не дают зрительную цель или право атаковать. Слух обновляет отметки источников и линии на протяжении активного интереса/исследования/испуга; сроки хранения обслуживает общая очередь. Положение источника берётся из услышанного события, а не из текущей позиции скрытого игрока.

Атакующий летун обводится красным OBB тела на протяжении фазы пикирования/атакующего полувиража. Красный луч указывает на центр назначенного противника; признак атаки не требует уже нанесённого урона. Снимок позы готовится владельцем, мировой отладчик рисует только очередь через HUD().world_prims.


Подписи одного владельца группируются в колонку у центра тела с постоянным экранным шагом. Режим [АТАКА] сохраняется при ожидании пути, рядом выводится фактическая фаза/причина ожидания; красные OBB и луч — только стадия удара. Шейпы опасностей сохраняются без лучей от наблюдателя. Публикация диагностики летуна не прекращается только потому, что CanControl запретил движение. Удаляемые сущности слой отрисовки не разыменовывает.

Известные аномалии выводятся одной строкой на наблюдателя: ID через запятую, без повторов. Шейп одной аномалии рисуется один раз на кадр для всех наблюдателей; лучей от монстров к аномалиям нет. Остальные события сохраняют отдельные строки.

## Независимые категории отрисовки

- `monster_debug_3d_text on/off` — только подписи в 3D: поведение, чувства, цели, источники и таймеры.
- `monster_debug_3d_shapes on/off` — только 3D-фигуры: линии, пути, сферы, звуковые кольца и боксы попаданий.
- `monster_debug_hud on/off` — экранные замеры и счётчики. `monster_debug_hud reset` сбрасывает замеры.

Каждый переключатель независим, по умолчанию выключен. Можно оставить фигуры и HUD без надписей:

```text
monster_debug_3d_shapes on
monster_debug_3d_text off
monster_debug_hud on
```

`monster_logic on/off/config` управляет новой логикой. Для отладки используются только `monster_debug_3d_shapes`, `monster_debug_3d_text` и `monster_debug_hud`; старые псевдонимы удалены.
